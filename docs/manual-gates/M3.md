# M3 manual gate

Checks that only a human on a real Mac, with Unity Editors and the Claude desktop app, can run
(CONTRIBUTING.md, "Rules", rule 2). Run them on the Mac that ran the spike, with the Unity project
the spike used, record the results as a comment on the pinned Build plan issue, and only then close
the milestone and tag `v0.3.0` (docs/design.md, Appendix A, "Stage 4: milestone gates and tags").

The first check adds the captures M3's code is built against; the M3 issues add their checks after
it, and [#96](https://github.com/weslo/upool/issues/96) completes the gate.

## Capture the M3 replies

From [#86](https://github.com/weslo/upool/issues/86). M3 drives Editors through the Unity CLI and
guards scene work with a `PreToolUse` hook, and the spike captured none of the replies those read.
This check adds them as new captures, which are never edited afterwards (CONTRIBUTING.md, "Rules",
rule 1; testdata/README.md, "Re-capturing"). The decisions #12, #17, #29 and #30 wait on what they
show. Every Unity CLI capture goes through `scripts/capture-unity.sh`, which keeps stdout and stderr
apart and records the exit code.

**Needs:**
- the Unity CLI (1.0.0-beta.13 or later) and the Editor version the project uses;
- the Claude desktop app;
- `jq` and Go;
- the spike's Unity project, its Editor closed;
- a checkout of upool on this check's pull request branch, `issue-86`, which is where the new
  files go.

1. **Set up.** Build upool, make the project a pool of two slots if it is not one already, and name
   what the steps use. From the upool checkout:

   ```bash
   git switch issue-86 && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   (cd "$repo" && { upool status >/dev/null 2>&1 || upool init --slots 2; } && upool status)
   slot1=$repo/.claude/worktrees/slot-1
   slot2=$repo/.claude/worktrees/slot-2
   cap() { "$upool/scripts/capture-unity.sh" --var repo="$repo" "$@"; }
   unity --version
   ```

   **Look for:** `unity --version` 1.0.0-beta.13 or later, and both slots `ready`.

2. **Replies that need no Editor.** In the same shell, from the upool checkout. The verify pair
   runs on a clean slot and on the other slot with one `.meta` file moved out, then put back:

   ```bash
   cap license-status license status --format json
   cap projects-verify-pass projects verify --strict "$slot1" --format json
   meta=$(git -C "$slot2" ls-files 'Assets/*.meta' | head -n 1)
   aside=$(mktemp)
   mv "$slot2/$meta" "$aside"
   cap projects-verify-fail projects verify --strict "$slot2" --format json
   mv "$aside" "$slot2/$meta"
   git -C "$slot2" status --porcelain
   cap cache-key-project-path-rejected cache key --project-path "$repo" --format json
   (cd /tmp && cap build-not-a-unity-project build --list-profiles --format json)
   (export UNITY_PROJECT_PATH=$repo && cap status-no-instances status --format json)
   ```

   **Look for:**
   - `capture-unity: unity exited N` for each, and a `.exit` file beside each capture;
   - the licence state in `license-status.json`;
   - `"success": true` in `projects-verify-pass.json`, and the removed `$meta` named in
     `projects-verify-fail.json`;
   - an empty `git status` for slot-2 once the file is back;
   - `INVALID_COMMAND_ARGS` in `cache-key-project-path-rejected.json`;
   - "Not a Unity project" in `build-not-a-unity-project.json`;
   - `STATUS_NO_INSTANCES` in `status-no-instances.json`.

3. **Unity's VCS set-up, on a throwaway clone.** `vcs doctor --fix` changes what it repairs, so it
   never runs in the project itself:

   ```bash
   scratch=$(cd "$(mktemp -d)" && pwd -P)/clone
   git clone -q "$repo" "$scratch"
   (cd "$scratch" && cap vcs-doctor-fix vcs doctor --fix "$scratch" --format json)
   (cd "$scratch" && cap vcs-merge-setup vcs merge-setup "$scratch" --format json)
   git -C "$scratch" status --short
   git -C "$scratch" config --local --list | grep -i -E 'merge|lfs|unity'
   rm -rf "$(dirname "$scratch")"
   ```

   **Look for:** both captures, with their exits, and what the last two commands show the fixes
   changed in the clone: files, git configuration, hooks. #30 decides from it, so write it into
   the rows in step 7.

4. **Editors.** A headless Editor in slot-1, opened as A33 says. Then a GUI Editor in slot-2, a path
   the Hub does not know, so that the CLI prints its registry warning. With both up, the first
   `eval` on the GUI Editor, and an `eval` from outside any project with no `UNITY_PROJECT_PATH`:

   ```bash
   cap open-headless open "$slot1" --args "-batchmode" --format json
   UNITY_PROJECT_PATH=$slot1 unity status --until-ready --timeout 180 --format json | jq -c .data
   cap open-gui-streams open "$slot2" --format json
   UNITY_PROJECT_PATH=$slot2 unity status --until-ready --timeout 180 --format json | jq -c .data
   (export UNITY_PROJECT_PATH=$slot2 && cap command-eval-first-call command eval \
     "return Application.unityVersion;" --format json)
   (cd /tmp && env -u UNITY_PROJECT_PATH "$upool/scripts/capture-unity.sh" --var repo="$repo" \
     command-eval-ambiguous-editor command eval "return Application.unityVersion;" --format json)
   ```

   **Look for:**
   - a launched PID in `open-headless`, and both Editors ready;
   - for #17, where `open-gui-streams` put the `Warning: … opening as a file path.` line:
     - in `open-gui-streams.stderr.txt`, if it went to stderr;
     - before the JSON in `open-gui-streams.raw.txt`, if it went to stdout;
   - in `command-eval-first-call`, either the `COMMAND_FAILED` first-call timeout or the version;
     the capture is whichever came;
   - `AMBIGUOUS_EDITOR` in `command-eval-ambiguous-editor.json`.

5. **Close both Editors:**

   ```bash
   unity close "$slot1" --format json | jq -c .data
   unity close "$slot2" --format json | jq -c .data
   unity status --format json | jq -c .data
   ```

   **Look for:** both closed, and no instance left.

6. **`PreToolUse` stdin for `Edit`, `Write` and `NotebookEdit`.** Register `scripts/capture-hook.sh`
   for `PreToolUse` in the project's own `.claude/settings.local.json`, beside upool's hooks
   (project scope, as A26 registers upool; never `~/.claude/settings.json`). Copy it outside
   `~/Documents` first, as the M2 captures did, and keep the settings to put back. It wraps
   nothing, so it allows every call:

   ```bash
   hookdir=~/.upool-capture-hooks
   mkdir -p "$hookdir" ~/.upool-capture
   cp "$upool/scripts/capture-hook.sh" "$hookdir/" && chmod 755 "$hookdir/capture-hook.sh"
   settings=$repo/.claude/settings.local.json
   cp "$settings" "$hookdir/settings.local.json.before"
   jq --arg hook "$hookdir/capture-hook.sh" '.hooks.PreToolUse = (.hooks.PreToolUse // []) +
     [{matcher: "Edit|Write|NotebookEdit",
       hooks: [{type: "command", command: $hook, args: ["PreToolUse"]}]}]' \
     "$hookdir/settings.local.json.before" >"$settings"
   jq -c '.hooks | keys' "$settings"
   ```

   Then start a desktop worktree session in the project, which lands in a slot, with this first
   prompt:

   ```text
   Using exactly these tools, in this order: with Write, create upool-capture.txt holding the line
   one; with Edit, change one to two in it; with Write, create upool-capture.ipynb, a Jupyter
   notebook with one code cell holding print(1); with NotebookEdit, change that cell to print(2).
   Then delete both files with rm.
   ```

   When it has replied, copy the first capture of each tool, then archive the session with the
   app's Archive button (A28), and put the settings back:

   ```bash
   cd "$upool" && for tool in Edit Write NotebookEdit; do
     pick=
     for f in ~/.upool-capture/PreToolUse-*.json; do
       [ -z "$pick" ] && [ "$(jq -r .tool_name "$f")" = "$tool" ] && pick=$f
     done
     name=$(printf '%s' "$tool" | tr '[:upper:]' '[:lower:]')
     [ -n "$pick" ] && jq . "$pick" | go run ./scripts/scrubpaths --var repo="$repo" \
       >"testdata/captures/hooks/pretooluse-$name.json"
   done
   cp "$hookdir/settings.local.json.before" "$settings"
   rm -rf "$hookdir" ~/.upool-capture
   (cd "$repo" && upool status)
   ```

   **Look for:**
   - three files under `testdata/captures/hooks/`, each with `hook_event_name: "PreToolUse"`, its
     `tool_name` and `tool_input`, and `cwd` a slot, `${repo}/.claude/worktrees/slot-N`;
   - the session's slot `needs-reset` once it is archived: the session deleted its files, so the
     slot is clean.

7. **Fill in the rows, then commit, check and push.**
   - In testdata/README.md, make each **pending** row for this check:
     - name the files written, keeping and naming any `*.stderr.txt`;
     - replace **pending** with the version and the date: the CLI's for a Unity reply, and the
       desktop app's and Claude Code's for a hook;
     - say what the capture showed, especially where a decision waits on it:
       - the warning's stream (#17);
       - the exit codes (#12);
       - what `verify --strict` reported (#29);
       - what the VCS set-up changed (#30).
   - Both checks see only what git does, so they run after the commit:

   ```bash
   cd "$upool"
   git status --short
   git add testdata/captures/unity testdata/captures/hooks testdata/README.md
   git commit -m 'Add the captures from the M3 gate check "Capture the M3 replies"'
   make check-paths check-captures
   go test ./internal/hooks -run TestClassifyEveryCapture
   git push
   ```

   **Look for:**
   - `git status` lists only the new captures and testdata/README.md;
   - both checks and the test pass before the push.

A capture that could not be recorded, or a failing check, fails this check: say so on the pull
request instead of pushing the files. The pool stays as it was; take it out as docs/manual-gates/
M2.md, "Afterwards", says, or keep it for the rest of the gate.

## First-call timeout

From [#84](https://github.com/weslo/upool/issues/84). The first `eval` on a freshly opened GUI
Editor timed out at 5,000 ms yet ran (spike §8 C.3), so `upool close`'s `save_all` re-queries after
that timeout by running `save_all` once more (A29). The fake `unity` replays the timeout and the
second call; only a real Editor shows that `upool close` keeps a change made in a freshly opened
Editor. Run it once M3's issues are merged, as part of
[#96](https://github.com/weslo/upool/issues/96).

**Needs:**
- the Unity CLI and the Editor version the project uses;
- the spike's Unity project, made a pool with a ready slot (the first check's step 1);
- a checkout of upool on `main` with `upool open` and `upool close` merged (#89, #90).

1. **Set up.** Build upool, then take a slot for the check. From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   slot=$(cd "$repo" && upool take gate-first-call)
   git -C "$slot" status --short
   ```

   **Look for:** a slot path, and an empty `git status`.

2. **Open a GUI Editor in the slot**, then make its first CLI call `upool close`'s `save_all`:

   ```bash
   (cd "$slot" && upool open --gui)
   ```

   As soon as it reports the Editor ready, in the Editor window, within the first seconds: open a
   scene the project tracks, move any object, and leave the scene unsaved, its title marked
   modified. Run no `unity` command and no `upool` command against the slot meanwhile.

   **Look for:** the scene marked modified in the Editor's title bar.

3. **Close it, then look at the scene on disk:**

   ```bash
   (cd "$slot" && upool close; echo "exit $?")
   git -C "$slot" status --short
   ```

   **Look for:**
   - `exit 0`, and the Editor gone;
   - the scene modified (` M …/<scene>.unity`) in `git status`: the change was saved before the
     Editor closed, whether or not the first `save_all` timed out. The timeout did not recur in
     #86's capture, so this check may pass without it; it still fails if `close` discards the
     change.

4. **Afterwards**, put the scene back and release the slot:

   ```bash
   git -C "$slot" checkout -- .
   git -C "$slot" status --short
   (cd "$repo" && upool release gate-first-call && upool status)
   ```

   **Look for:** an empty `git status`, and the slot back to `ready` or `needs-reset`.

A change missing from disk after `upool close` fails this check: record it on the Build plan issue
with the Editor version and what `upool close` printed.

## VCS set-up

From [#88](https://github.com/weslo/upool/issues/88). `upool init` runs none of Unity's VCS
set-up, and `upool doctor` reports what `unity vcs doctor` finds, check-only (A35). The fake
`unity` shows which calls upool makes; only the real project shows that `init` leaves the
repository's git files and configuration alone and that `doctor` lists the real findings. It needs
no Editor, and it runs on a throwaway clone with `HOME` pointed at a scratch directory, so neither
the project nor `~/.upool` is touched.

**Needs:**
- the Unity CLI;
- the spike's Unity project, its Editor closed and its Library current at HEAD;
- `jq`, Go, and a checkout of upool on `main` with #88 merged.

1. **Set up a throwaway clone with the project's Library.** From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   gate=$(cd "$(mktemp -d)" && pwd -P)
   mkdir "$gate/home"
   git clone -q "$repo" "$gate/clone"
   cp -cR "$repo/Library" "$gate/clone/Library"
   ```

   `cp -cR` clones the Library without copying its bytes, and without `-p` its files are newer
   than the clone's scripts, so `init`'s staleness check accepts it.

   **Look for:** no errors.

2. **Compare the check-only reply with the capture #88 recorded:**

   ```bash
   (cd "$gate/clone" && "$upool/scripts/capture-unity.sh" -o "$gate" --var repo="$repo" \
     vcs-doctor vcs doctor "$gate/clone" --format json)
   diff <(jq '.data.findings | map(.code)' "$upool/testdata/captures/unity/vcs-doctor.json") \
     <(jq '.data.findings | map(.code)' "$gate/vcs-doctor.json")
   git -C "$gate/clone" status --short
   ```

   **Look for:** `capture-unity: unity exited 4`, no `diff` output (or only the findings the
   project has since fixed or gained), and an empty `git status`: without `--fix`, `vcs doctor`
   writes nothing.

3. **`upool init` leaves the git set-up alone.** Record the files and configuration Unity's set-up
   would change, run `init`, and record them again:

   ```bash
   snap() { (cd "$gate/clone" && cat .gitattributes; echo '--- .gitignore'; cat .gitignore
     echo '--- hooks'; ls .git/hooks | grep -v '\.sample$'; echo '--- config'
     git config --local --list); }
   snap >"$gate/before.txt"
   (cd "$gate/clone" && HOME="$gate/home" upool init)
   snap >"$gate/after.txt"
   diff "$gate/before.txt" "$gate/after.txt" && echo unchanged
   ```

   **Look for:** `init` cloning `slot-1` and exiting 0, then `unchanged`. If the project's
   `.gitignore` did not already ignore `.claude/worktrees/`, `init` adds that one line, and the
   `diff` shows it and nothing else.

4. **`upool doctor` lists the findings:**

   ```bash
   (cd "$gate/clone" && HOME="$gate/home" upool doctor; echo "exit $?")
   ```

   **Look for:**
   - a `warn  vcs` line per finding of step 2, with its code, severity and message;
   - a last `warn  vcs` line naming `unity vcs doctor --fix` and `unity vcs merge-setup`;
   - `exit 0`, if every other check passes: the VCS findings warn and never fail `doctor`.

5. **Afterwards**, remove the clone and the scratch `HOME`, and check that the project is as it was:

   ```bash
   rm -rf "$gate"
   git -C "$repo" worktree list
   git -C "$repo" status --short
   ```

   **Look for:** the main checkout alone in `git worktree list`, and the `git status` it had before.

A change to `.gitattributes`, the hooks or the git configuration from `init`, a missing finding
in `doctor`'s output, or a `vcs` line that fails `doctor` fails this check.

## Open

From [#89](https://github.com/weslo/upool/issues/89). `upool open` charges the Editor ledger,
opens the slot's Editor, headless unless `--gui` (A36), and waits until it is ready or has exited.
The fake `unity` replays `unity open` and `unity status --until-ready`; only real Editors show how
long a real open takes and that the ledger records them. `upool status` does not show Editors yet,
so the check reads `~/.upool/editors.json`.

**Needs:**
- the Unity CLI and the Editor version the project uses;
- the spike's Unity project, a pool with two `ready` slots whose Libraries are current (warm), and
  no Editor open in either;
- `jq`, Go, and a checkout of upool on `main` with #89 merged.

1. **Set up, and take two slots.** From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   gui=$(cd "$repo" && upool take gate-open-gui)
   headless=$(cd "$repo" && upool take gate-open-headless)
   jq . ~/.upool/editors.json 2>/dev/null || echo "no ledger yet"
   ```

   **Look for:** two slot paths, and no Editor in the ledger.

2. **A GUI Editor:**

   ```bash
   (cd "$gui" && time upool open --gui)
   jq . ~/.upool/editors.json
   ```

   **Look for:**
   - `opened slot-N's Editor gui, process P: ready, charged 2.5 GB`, with `real` around 21 s or less
     (spike §8 C.1), and the Editor's window;
   - one entry in the ledger: `project` the slot, `pid` P, `mode` `gui`, `opened_by_upool` true,
     `cold_import` false, `charge_gb` 2.5.

3. **A headless Editor, the default:**

   ```bash
   (cd "$headless" && time upool open)
   jq . ~/.upool/editors.json
   ps -o pid,command -p "$(jq '.editors[1].pid' ~/.upool/editors.json)"
   ```

   **Look for:** `opened slot-N's Editor headless, …: ready, charged 2.5 GB` within about 57 s
   (spike §8 B.1), a second ledger entry with `mode` `headless`, and `-batchmode` in its process's
   command line.

4. **Afterwards**, close both Editors and release the slots:

   ```bash
   unity close "$gui" --format json | jq -c .data
   unity close "$headless" --format json | jq -c .data
   (cd "$repo" && upool release gate-open-gui && upool release gate-open-headless && upool status)
   ```

   **Look for:** both Editors closed, both slots back to `ready`. The ledger drops their entries at
   its next update, once their processes are gone.

An open that is not ready, a missing or wrong ledger entry, or a headless Editor without
`-batchmode` fails this check.

## Save then close

scene closed gracefully in 12.1 s with no dialog, and the change was gone (spike §8 C.4). `upool
close` runs `save_all` first and closes only once the save has succeeded; `save_all` then `close`
kept the change (spike §8 C.5). The fake `unity` shows the order of the calls; only a real Editor
shows the change on disk.

**Needs:**
- the Unity CLI and the Editor version the project uses;
- the spike's Unity project, a pool with a `ready` slot whose Library is current;
- Go, and a checkout of upool on `main` with #89 and #90 merged.

1. **Set up, take a slot and open its Editor with its window.** From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   slot=$(cd "$repo" && upool take gate-save-close)
   (cd "$slot" && upool open --gui)
   git -C "$slot" status --short
   ```

   **Look for:** the Editor ready, and an empty `git status`.

2. **Dirty a scene.** In the Editor window, open a scene the project tracks, move any object, and
   leave the scene unsaved, its title marked modified.

3. **Close it with upool, then look at the scene on disk:**

   ```bash
   (cd "$slot" && upool close; echo "exit $?")
   git -C "$slot" status --short
   jq . ~/.upool/editors.json
   ```

   **Look for:**
   - `saved and closed slot-N's Editor, process P`, `exit 0`, and the Editor gone;
   - the scene modified in `git status` (` M …/<scene>.unity`);

4. **Afterwards**, put the scene back and release the slot:

   ```bash

   (cd "$repo" && upool release gate-save-close && upool status)
   ```

   **Look for:** the slot back to `ready`.

A clean `git status` after `upool close`, a close that went ahead after a failed save, or a slot
whose Editor stays in the ledger fails this check.

## Scene list

**Needs:**
- the Unity CLI and the Editor version the project uses;
- the spike's Unity project, a pool with a `ready` slot whose Library is current;

   ```bash

   ```

   **Look for:** the file naming that scene under `sceneSetups`.

   ```bash
   (cd "$slot" && upool open)

   (cd "$slot" && upool close --json | jq -c .data)
   ```

   ```bash
   (cd "$slot" && upool close)
   (cd "$repo" && upool release gate-scene-list && upool status)
   ```

   **Look for:** the slot back to `ready`.

An Untitled scene in step 3, or `sceneSetups: []` in the file after step 2, fails this check.

## Release with an Editor

From [#92](https://github.com/weslo/upool/issues/92). `upool release` saves and closes the Editor
upool opened in the slot before it judges the slot clean, so the Editor's unsaved work lands in the
slot and parks it. The fake `unity` shows the order of the calls, and `take`'s `editor-running`
skip; only a real Editor shows the change saved and the Editor gone.

**Needs:**
- the Unity CLI and the Editor version the project uses;
- the spike's Unity project, a pool with a `ready` slot whose Library is current;
- `jq`, Go, and a checkout of upool on `main` with #89 to #92 merged.

1. **Set up, take a slot and open its Editor with its window.** From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   slot=$(cd "$repo" && upool take gate-release-editor)
   (cd "$slot" && upool open --gui)
   ```

   **Look for:** the Editor ready.

2. **Dirty a scene.** In the Editor window, open a scene the project tracks, move any object, and
   leave the scene unsaved.

3. **Release the slot with the Editor still open:**

   ```bash
   pid=$(jq --arg s "$slot" '.editors[] | select(.project == $s) | .pid' ~/.upool/editors.json)
   (cd "$repo" && upool release gate-release-editor; echo "exit $?")
   git -C "$slot" status --short
   ps -p "$pid" || echo "Editor gone"
   jq . ~/.upool/editors.json
   ```

   **Look for:**
   - `saved and closed slot-N's Editor, process P`, then `parked slot-N, which is dirty`, with a
     warning naming the scene, and `exit 0`;
   - the scene modified in `git status`;
   - `Editor gone`, and no entry for the slot in the ledger.

4. **Afterwards**, put the scene back. The slot stays `parked`: resolve it as
   docs/manual-gates/M1.md, "Afterwards", says, since nothing in M3 hands a parked slot out again.

   ```bash
   git -C "$slot" checkout -- .
   (cd "$repo" && upool status)
   ```

A release that leaves the Editor running, loses the change, or resets the slot fails this check.

## Crash recovery

From [#93](https://github.com/weslo/upool/issues/93). An Editor that dies without closing leaves
its ledger entry charged and its slot's `Temp/UnityLockfile`, which makes Unity refuse the project
as already open. `upool doctor` reports the dead Editor; `upool doctor --fix` takes it out of the
ledger and deletes the slot's `Temp/`, but only when `unity status` lists no Editor in the slot
(docs/design.md, "Editors: budget by RAM, serialize cold imports as a courtesy, target by variable
and by path"). It also reports the licence. The fake `unity` stands in for both; only a real crash
shows that the slot opens again.

**Needs:**
- the Unity CLI and the Editor version the project uses;
- the spike's Unity project, a pool with a `ready` slot whose Library is current;
- `jq`, Go, and a checkout of upool on `main` with #89 to #93 merged.

1. **Set up, take a slot and open its Editor.** From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   slot=$(cd "$repo" && upool take gate-crash)
   (cd "$slot" && upool open)
   pid=$(jq --arg s "$slot" '.editors[] | select(.project == $s) | .pid' ~/.upool/editors.json)
   echo "$pid"
   ```

   **Look for:** the Editor ready, and its process ID.

2. **Crash it:**

   ```bash
   kill -9 "$pid"
   ls "$slot/Temp/UnityLockfile"
   (cd "$repo" && upool doctor; echo "exit $?")
   ```

   **Look for:**
   - the lock file still there;
   - a `fail  editors` line naming the slot and process `$pid`, saying `upool doctor --fix` removes
     it;
   - a `unity-licence` line with the licence, as information;
   - `exit 1`.

3. **Recover:**

   ```bash
   (cd "$repo" && upool doctor --fix; echo "exit $?")
   ls "$slot/Temp" || echo "Temp gone"
   jq . ~/.upool/editors.json
   ```

   **Look for:** a `pass  editors` line reading `fixed: removed …, and its Temp/, since unity
   status lists no Editor with it open`, `Temp gone`, and no entry for the slot in the ledger.

4. **The slot opens again:**

   ```bash
   (cd "$slot" && upool open)
   ```

   **Look for:** the Editor ready, with no "project is already open" error.

5. **Afterwards**, close the Editor and release the slot:

   ```bash
   (cd "$slot" && upool close)
   (cd "$repo" && upool release gate-crash && upool status)
   ```

   **Look for:** the slot back to `ready`.

A dead Editor `doctor` does not report, a `Temp/` left behind by `--fix` with no Editor listed, or
an open that fails afterwards, fails this check.

## Lane guard

From [#95](https://github.com/weslo/upool/issues/95). `upool init` registers a `PreToolUse` hook for
`Edit|Write|NotebookEdit` in the project's `.claude/settings.local.json`, beside upool's other
hooks (A26), with `"onFailure": "block"`. It denies a write to a `.unity`, `.prefab`, `.asset` or
`.meta` file in a slot whose lease is in the script lane, and a hook that fails denies too
(docs/design.md, "Lanes: scripts in parallel, scenes one at a time, `.meta` never regenerated").
The tests replay the captured requests; only the desktop app shows Claude Code honouring the
denial and `onFailure`.

**Needs:**
- the Claude desktop app, with Claude Code 2.1.295 or later (`onFailure`);
- the spike's Unity project, a pool with a `ready` slot, and no Editor open in it;
- `jq`, Go, and a checkout of upool on `main` with #95 merged.

1. **Set up, and register the guard.** A project registered before #95 needs `upool init` again,
   which adds the guard and leaves everything else as it was. From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   upool=$(pwd -P)
   make build && export PATH="$upool/bin:$PATH"
   repo=<the Unity project's main checkout, absolute>
   (cd "$repo" && upool init && upool doctor)
   jq -c '.hooks.PreToolUse' "$repo/.claude/settings.local.json"
   scene=$(git -C "$repo" ls-files 'Assets/*.unity' | head -n 1)
   echo "$scene"
   ```

   **Look for:** `pass  hook-settings` naming PreToolUse, a `PreToolUse` group with the matcher
   `Edit|Write|NotebookEdit` and `"onFailure":"block"` on upool's handler, and a scene path.

2. **A denied edit.** Start a desktop worktree session in the project, which lands in a slot in the
   script lane, with this prompt, putting the scene path from step 1 in place of `<scene>`:

   ```text
   With the Edit tool, add the line "# upool lane check" at the end of <scene>. Do not use any
   other tool to change it.
   ```

   Then, in Terminal, find the session's slot and check the scene:

   ```bash
   (cd "$repo" && upool status)
   slot=<the slot path status shows leased to the session>
   git -C "$slot" status --short
   ```

   **Look for:**
   - Claude reporting the edit blocked, with upool's reason: the slot is in the script lane, and
     `upool take <branch> --lane scene`;
   - an empty `git status`: the scene is unchanged.

3. **A failed hook denies too.** Make the upool the hook runs unable to start, then ask again in the
   same session:

   ```bash
   hook=$(jq -r '.hooks.PreToolUse[].hooks[] | select(.args == ["hook", "pre-tool-use"]) |
     .command' "$repo/.claude/settings.local.json")
   chmod -x "$hook"
   ```

   ```text
   Try that same edit once more, with the Edit tool only.
   ```

   **Look for:** the edit blocked again, this time as a hook error rather than upool's reason, and
   an empty `git -C "$slot" status --short`. Then put the binary back:

   ```bash
   chmod +x "$hook"
   ```

4. **Afterwards**, archive the session with the app's Archive button (A28), then check the slot:

   ```bash
   (cd "$repo" && upool status)
   ```

   **Look for:** the session's slot `needs-reset` or `ready`: nothing was written.

An edit that goes through in step 2 or step 3 fails this check. The hole the design documents
stays open: a shell command that writes the scene, such as `cp` or a redirect, is not seen.
