# M2 manual gate

Checks that only a human on a real Mac with the Claude desktop app can run (CONTRIBUTING.md,
"Rules", rule 2). Run them on the Mac that ran the spike, with the Unity project the spike used,
record the results as a comment on the pinned Build plan issue, and only then close the milestone
and tag `v0.2.0` (docs/design.md, Appendix A, "Stage 4: milestone gates and tags").

From [#81](https://github.com/weslo/upool/issues/81). Checks 1 to 8 are the ones the M2 issues
added, in the order one run needs them; checks 9 to 12 are the end-to-end checks. They run in
order in one shell, which holds the variables "Before you start" sets. Each check archives the
desktop sessions it starts before the next begins, unless it says to leave one open. There is no
`SessionEnd` check: upool registers no `SessionEnd` hook (docs/contracts.md A25). The hook inputs
these checks rest on were captured in #148; the appendix keeps that procedure for a re-capture.

## Before you start

**Needs:** the Claude desktop app; Go, `jq`, the Unity CLI (1.0.0-beta.13 or later) and the Unity
Editor the project uses; a checkout of upool on `main` with this gate merged; and the spike's Unity
project, its Editor closed.

1. Build upool and put it first on `PATH`, from the upool checkout. A checkout under `~/Documents`
   is fine: the desktop app's hook helper runs a binary there (docs/contracts.md A24).

   ```bash
   upool_dir=$(pwd -P)
   git switch main && git pull --ff-only && make build
   export PATH="$upool_dir/bin:$PATH"
   upool --version
   ```

2. Name the pooled repository and make it a pool of two ready slots, if it is not one already, and
   name its pool's directory:

   ```bash
   repo=<the Unity project's main checkout, absolute>
   cd "$repo" && { upool status >/dev/null 2>&1 || upool init --slots 2; }
   pool=$(find ~/.upool/pools -maxdepth 1 -iname "$(basename "$repo")-*" | head -n 1)
   upool status && ls "$pool/state.json"
   ```

   **Look for:** the pool's slots `ready`, at least two of them, and `state.json` found.

3. Note when the gate starts, for check 11, and the versions for the result:

   ```bash
   gate_start=$(date '+%Y-%m-%d %H:%M:%S')
   sw_vers -productVersion; unity --version; git -C "$upool_dir" rev-parse --short HEAD
   ```

   The desktop app's version is in its About window.

## 1. Project registration

From [#173](https://github.com/weslo/upool/issues/173). `upool init` registers upool itself as
the project's hooks, `upool hook <event>` in exec form, in the project's own
`.claude/settings.local.json`; the desktop app runs hooks a project registers there, and upool
never writes `~/.claude/settings.json` (docs/contracts.md A26; A24). Built in a checkout under
`~/Documents`, as "Before you start" builds it, upool is the case A24 rests on: the desktop app's
helper runs a binary there but cannot read a file there.

**Needs:** "Before you start" done, so `init` has run in `$repo`; `jq`.

1. Look at what `init` registered, and run it again:

   ```bash
   jq '.hooks | {WorktreeCreate, WorktreeRemove, SessionStart}' "$repo/.claude/settings.local.json"
   cd "$repo" && upool init
   jq '.hooks // "no user-scope hooks"' ~/.claude/settings.json
   ```

   **Look for:** under each of the three events, exactly one group whose only handler is
   `{"type": "command", "command": "<upool_dir>/bin/upool", "args": ["hook", "<event>"]}`, with
   `worktree-create`, `worktree-remove` and `session-start` in turn, and any other hook the file
   had still there; the second `init` saying `$repo is already registered`, `the hooks run …` and
   `….claude/settings.local.json is up to date`; and no upool hook in `~/.claude/settings.json`.

2. Note the time, and start a desktop worktree session in the pooled repository with the first
   prompt `pwd`. When it has replied:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')   # before the session
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'hook-based worktree|WorktreeCreate hook|Skipped|worktree_hook_failed'
   ```

   **Look for:** `Created hook-based worktree "<name>" at` a slot, and no `worktree_hook_failed`.
   The two `Skipped …` lines, the per-machine config overlay and auto-trust "(provenance not
   vouched)", are expected for project hooks (#172). Archive the session.

## 2. Skill

From [#68](https://github.com/weslo/upool/issues/68) and
[#174](https://github.com/weslo/upool/issues/174). `upool init` installs the upool skill in the
project, at `.claude/skills/upool/SKILL.md` with a copy at `.agents/skills/upool/SKILL.md`, and
upserts upool's block into its `CLAUDE.md` and `AGENTS.md` (A26; docs/design.md, "Hooks route,
skills teach, leases and lanes keep agents from colliding": the three layers).

**Needs:** "Before you start" done, so `init` has run in `$repo`; Claude Code.

1. Look at what `init` wrote, and that nothing went under the home directory's agent folders:

   ```bash
   head -n 4 "$repo/.claude/skills/upool/SKILL.md"
   cmp "$repo/.claude/skills/upool/SKILL.md" "$repo/.agents/skills/upool/SKILL.md" && echo same
   grep -c '^<!-- upool:begin v' "$repo/CLAUDE.md" "$repo/AGENTS.md"
   ls -d ~/.claude/skills/upool ~/.agents/skills/upool 2>&1
   ```

   **Look for:** frontmatter with `name: upool` and a description, `same`, a count of `1` for each
   instruction file, and neither home-directory skill directory existing.

2. Start a desktop session in the pooled repository without a worktree, and ask the agent:

   ```text
   Which skills do you have? List each by name.
   ```

   **Look for:** `upool` in the list.

## 3. Desktop session lands in a slot

From [#78](https://github.com/weslo/upool/issues/78). The create hook's pooled branch gives a
session in a pooled repository a free slot, with the create hook's unconfirmed lease, and prints
only the slot's path. It locks the slot's worktree for the lease, which is a git write from the
desktop app's helper; the spike exercised git writes there only as `worktree add`. With no slot
free it waits 20 s, then fails, naming `upool refresh` (docs/design.md, "Route Claude Code's
worktrees through the pool: three branches in one hook"; docs/contracts.md (a); A11).

**Needs:** the hooks registered as in check 1, step 1; a pool of at least two
ready slots, open in the desktop app, its main checkout's absolute path in `repo`.

1. Note the time and the slots:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   cd "$repo" && upool status
   ```

2. Start a desktop worktree session in the pooled repository with the first prompt `pwd`. When it
   has replied:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'hook-based worktree|Auto-trusted worktree|start-timing|worktree_hook_failed'
   git -C "$repo" worktree list --porcelain
   ```

   **Look for:**
   - The reply's `pwd` is `$repo/.claude/worktrees/slot-N`.
   - `main.log` shows `Created hook-based worktree` at that path and `Auto-trusted worktree …
     (inherited from …)`, with no `worktree_hook_failed`.
   - The session's `[CCD start-timing]` line has `worktree=` under 200 ms.
   - In `git worktree list`, the slot's entry has `locked upool lease <lease_id>`.

3. With the first session still live, start a second one the same way. Then run step 2's commands
   and `upool status`.

   **Look for:** the second session in another slot, never the first session's path and no
   `already in use` refusal. If no slot was free, it is refused with `worktree_hook_failed` after
   about 20 s, with upool's stderr naming `upool refresh`.

4. A minute later, past `confirm_timeout`:

   ```bash
   upool status
   ```

   **Look for:** no slot `leased-unconfirmed`, and each live session's slot `leased`: its
   `SessionStart` confirmed it (#77).

## 4. Environment

From [#77](https://github.com/weslo/upool/issues/77). The `SessionStart` hook reads the slot from
stdin `cwd`; on `startup` it confirms the session's lease, as `upool take --confirm` does, with the
session's CLI as its holder, and exports `UNITY_PROJECT_PATH` through `CLAUDE_ENV_FILE`. On
`resume` and `compact` it exports the variable again and records the new holder, but re-copies no
agent file and runs no reset (docs/design.md, "Environment, confirmation and release";
docs/contracts.md (b); A6; A14).

**Needs:** a desktop session in one of the pool's slots, as check 3 starts one; `jq`; the pooled
repository's main checkout in `repo` and its pool's directory under `~/.upool/pools/` in `pool`.

1. Start a desktop worktree session in the pooled repository, with the first prompt:

   ```text
   Run echo "$UNITY_PROJECT_PATH" and pwd, and report what they print.
   ```

   **Look for:** both print the same slot, under `$repo/.claude/worktrees/`.

2. More than a minute after the session started, past `confirm_timeout`:

   ```bash
   cd "$repo" && upool status
   jq '.slots[] | select(.lease) | {name, state, confirmed: .lease.confirmed,
     holder_pid: .lease.holder_pid}' "$pool/state.json"
   ps -o pid,command -p "$(jq '.slots[] | select(.lease) | .lease.holder_pid' "$pool/state.json")"
   ```

   **Look for:** the session's slot `leased`, not `leased-unconfirmed`, with `confirmed: true`,
   and its `holder_pid` a running Claude Code CLI (`…/claude.app/Contents/MacOS/claude`).

3. Ask the session to append the line `<!-- environment check -->` to the slot's `CLAUDE.md`. Run
   `/compact` in it, then repeat step 1's prompt; quit the desktop app, open it again, open the
   session and repeat the prompt once more. After each, run step 2's `jq` and `ps`, and:

   ```bash
   grep -c 'environment check' "$repo"/.claude/worktrees/*/CLAUDE.md
   ```

   **Look for:** the slot after each prompt, as in step 1; the slot still `leased`, its lease
   confirmed, and after the reopen a `holder_pid` that is the session's new CLI process (A14);
   and the slot's `CLAUDE.md` still holding the line, once: neither hook run re-copied it.

## 5. Top-up

From [#79](https://github.com/weslo/upool/issues/79). After a startup's confirm, the
`SessionStart` hook spawns `upool refresh` detached in the pool's main checkout. It resets each
`needs-reset` slot, then clones until the pool has `ready` slots ready or `max_slots` slots, and
appends its output to `~/.upool/pools/<repo-key>/refresh.log`. `status` announces it while it runs
(docs/design.md, "Environment, confirmation and release"; docs/contracts.md (e) `refresh_job`; (f)
transitions 1 and 20; A4; A19).

**Needs:** the hooks registered as in check 1, step 1; a pool with one ready slot
and room below `max_slots`, open in the desktop app, its main checkout's absolute path in `repo`
and its pool's directory under `~/.upool/pools/` in `pool`.

1. Start a desktop worktree session in the pooled repository, with the first prompt `pwd`. As soon
   as it has replied:

   ```bash
   cd "$repo" && upool status
   ```

   **Look for:** the session's slot `leased`, and a line `refreshing: upool refresh is running as
   process <pid>, since <time>`.

2. About 30 s later:

   ```bash
   upool status
   tail -n 5 "$pool/refresh.log"
   ```

   **Look for:** no `refreshing:` line, a new slot `ready`, and `cloned slot-N` with `the pool has
   1 ready, as ready = 1 asks` at the end of `refresh.log`.

3. Archive the session, then start another the same way. When it has replied, run step 2's
   commands again.

   **Look for:** the new session in the ready slot, and the archived session's slot, `needs-reset`
   after the archive, reset by the refresh this session spawned: `reset slot-N` in
   `refresh.log` and that slot `ready`.

## 6. Archive

From [#73](https://github.com/weslo/upool/issues/73). About a second after a session is archived
the desktop app sends `WorktreeRemove`; the hook judges the slot with git reads alone, marks it
`needs-reset` when clean or `parked` when dirty, clears the lease and exits 0, and the app logs
"Removed hook-based worktree" with the slot still on disk (docs/contracts.md (a), WorktreeRemove
rules; (f) transitions 8 and 9; spike §8 A.6, A.8).

**Needs:** a desktop session that ran in one of the pool's slots, as check 4's did; the pooled
repository's main checkout in `repo`.

1. Note the time, the slot the session is in and its state:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   cd "$repo" && upool status
   ```

2. Archive the session, then:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'Removing worktree|Removed hook-based worktree|WorktreeRemove'
   upool status
   ```

   **Look for:** `Removed hook-based worktree` within a second of the archive, and the session's
   slot `needs-reset` with no lease.

3. Start another desktop session in a slot, ask it to run `echo kept > upool-archive-check.txt`,
   note the time again as in step 1, and archive it. Then run step 2's commands, and:

   ```bash
   ls "$repo"/.claude/worktrees/*/upool-archive-check.txt
   ```

   **Look for:** `Removed hook-based worktree`; the slot `parked`; and the file still in it.

## 7. Subagent worktree

From [#71](https://github.com/weslo/upool/issues/71). The create hook gives a subagent's request
an ordinary worktree, detached at the repository's HEAD, at
`<repo>/.claude/worktrees/agent-<hex>`, records it in the pool's `state.json` and never leases it
a slot (docs/design.md, "Route Claude Code's worktrees through the pool: three branches in one
hook"). Subagent requests come from the bundled CLI, which can read `~/Documents` (spike §9 F.2).

**Needs:** the hooks registered as in check 1, step 1; `jq`; the pooled
repository open in the desktop app, its main checkout's absolute path in `repo` and its pool's
directory under `~/.upool/pools/` in `pool`.

1. Note the slots' state:

   ```bash
   jq '[.slots[] | {name, state}]' "$pool/state.json"
   ```

2. In the desktop app, start a session in the pooled repository **without** a worktree, as the
   spike's Test F parent session was, so that the subagents' worktrees are the only ones made, and
   ask:

   ```text
   Run two subagents, each with worktree isolation, that each run pwd and git status and report
   what they print.
   ```

3. When both have reported:

   ```bash
   git -C "$repo" worktree list
   jq '.agent_worktrees, [.slots[] | {name, state}]' "$pool/state.json"
   ```

   **Look for:** each subagent's `pwd` under `$repo/.claude/worktrees/agent-` followed by 17 hex
   digits, with a clean `git status`; both worktrees in `git worktree list`, `(detached HEAD)`;
   two `agent_worktrees` entries with those paths, the session's `parent_session_id` and a
   `parent_pid`; and the slots in the state step 1 showed, none of them leased.

## 8. Other repositories are untouched

From [#173](https://github.com/weslo/upool/issues/173). upool's hooks run only in the projects
`init` registers (A26), so a session in any other repository gets the desktop app's own worktree,
with no upool hook involved.

**Needs:** a git repository under `~/Documents` that is not a pool, with at least one commit, open
in the desktop app. A new one will do:

```bash
other=~/Documents/upool-not-a-pool
git init -q "$other" && git -C "$other" commit -q --allow-empty -m "Not a pool"
```

1. Note the time, and start a desktop worktree session in `$other` with the first prompt `pwd`.
   When it has replied:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')   # before the session
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'Creating worktree|WorktreeHooks|hook-based worktree|worktree_hook_failed'
   ```

   **Look for:** `Creating worktree for session` and no `WorktreeHooks` or `hook-based` line: the
   app made the worktree itself. Archive the session, then:

   ```bash
   rm -rf "$other"
   ```

## 9. Three sessions in a row

The first end-to-end check: three desktop worktree sessions in the pooled repository, one after
another, each archived before the next. Each lands in a slot, a reused slot is at base by the time
the agent first runs `git status`, and after a change to the main checkout's
`.claude/settings.local.json` the slot's copy matches it (#81; docs/design.md, "Slot lifecycle:
seed only from a Library current at HEAD, refresh on handout, reset without `-x`"; A5).

**Needs:** every earlier session archived, and the pool with no slot `leased`.

1. Change the main checkout's `.claude/settings.local.json`, keeping a copy to put back:

   ```bash
   settings="$repo/.claude/settings.local.json"
   cp "$settings" "$settings.gate-copy" 2>/dev/null || echo '{}' >"$settings.gate-copy"
   jq '. + {"upoolGateMarker": 10}' "$settings.gate-copy" >"$settings"
   ```

2. Three times over: note the time, start a desktop worktree session in the pooled repository
   with the first prompt below, and when it has replied run the commands and archive it.

   ```text
   Run git status, pwd and cat .claude/settings.local.json, and report exactly what they print.
   ```

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')   # before each session
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'Created hook-based worktree|worktree_hook_failed'
   upool status
   ```

   **Look for:** each session's `pwd` under `$repo/.claude/worktrees/slot-`; its `git status`
   with `HEAD detached at` the pool's base and nothing to commit, for a slot that held an earlier
   session too; its `settings.local.json` holding `"upoolGateMarker": 10`; `Created hook-based
   worktree` for each and no `worktree_hook_failed`; and, once each is archived, its slot
   `needs-reset` or `ready`, never `parked`.

3. Put the settings back:

   ```bash
   mv "$settings.gate-copy" "$settings"
   ```

## 11. Handout timing

The third end-to-end check: every slot handout in this run took under 200 ms (#81; spike §8 A.5;
spike §9 E.5).

```bash
awk -v since="$gate_start" -v slots="$repo/.claude/worktrees/slot-" '
  substr($0, 1, 19) < since { next }
  /Using worktree/ && index($0, slots) { session[$NF] = 1 }
  /\[CCD start-timing\]/ {
    for (id in session) if (index($0, id) && match($0, /worktree=[0-9]+ms/))
      print id, substr($0, RSTART, RLENGTH)
  }' ~/Library/Logs/Claude/main.log
```

**Look for:** a line for each session that landed in a slot since the gate started, each with
`worktree=` under 200 ms. Sessions outside the pool, check 8's, are not counted.

## Appendix: capture the M2 hook inputs

From [#148](https://github.com/weslo/upool/issues/148). Three M2 decisions need hook inputs, and
one timing, that the spike never captured: A11 (#16), how long the desktop app waits for a create
hook; A14 (#19), `SessionStart` for the sources other than `startup`; and A15 (#20),
`WorktreeRemove` and `SessionEnd` from a logged-in interactive CLI session (docs/contracts.md,
"Open questions").
This check adds them as new files under `testdata/captures/hooks/`, which are never edited
afterwards (CONTRIBUTING.md, "Rules", rule 1; testdata/README.md, "Re-capturing").

It needs no M2 code. The hooks it registers are `scripts/capture-hook.sh`, which saves each stdin
under `~/.upool-capture/`, wrapping a few lines of sh and git. #148 ran it and its captures are
in; the gate does not run it again. To re-capture, run it before check 1, on a branch of your own
for the new files: it replaces the four events' hooks in `~/.claude/settings.json` while it runs,
and step 6 puts the file back as it was.

**Needs:** the Claude desktop app; a logged-in Claude Code CLI, `claude`, in Terminal; `jq` and Go;
a checkout of upool on a branch for the new files; and, for the desktop steps, a repository open in
the desktop app: the upool checkout will do. Each desktop session in steps 3 and 4 must be started
with the app's worktree option on, or the app runs it in the checkout itself and calls no create
hook: check `main.log` for `Creating worktree for session`.

1. Set up the capture hooks outside `~/Documents`, where the app's create-hook helper cannot read,
   and a scratch repository for the CLI session. `desk` is the desktop steps' repository. From the
   upool checkout:

   ```bash
   git switch issue-148 && git pull --ff-only
   upool=$(pwd -P)
   desk=$upool
   cap=~/.upool-capture-hooks
   scratch=~/upool-capture-repo
   mkdir -p "$cap" ~/.upool-capture
   cp scripts/capture-hook.sh "$cap/"
   cat >"$cap/create.sh" <<'EOF'
   #!/bin/sh
   # A WorktreeCreate hook for the M2 hook captures (docs/manual-gates/M2.md): it makes the
   # worktree Claude Code would make, <cwd>/.claude/worktrees/<name> on a branch <name>, and prints
   # its path, with sh, sed and git alone. With a file named slow beside it, it first logs the
   # time, sleeps 30 s, and logs the time again before it prints (A11).
   set -eu
   here=$(cd "$(dirname "$0")" && pwd -P)
   req=$(cat)
   field() {
   	printf '%s\n' "$req" | sed -n "s/.*\"$1\"[[:space:]]*:[[:space:]]*\"\([^\"]*\)\".*/\1/p"
   }
   cwd=$(field cwd)
   name=$(field name)
   if [ -e "$here/slow" ]; then
   	echo "start $(date '+%Y-%m-%d %H:%M:%S')" >>"$here/timeout.log"
   	sleep 30
   fi
   git -C "$cwd" worktree add -q "$cwd/.claude/worktrees/$name" >&2
   if [ -e "$here/slow" ]; then
   	echo "printed $(date '+%Y-%m-%d %H:%M:%S')" >>"$here/timeout.log"
   fi
   printf '%s\n' "$cwd/.claude/worktrees/$name"
   EOF
   chmod 755 "$cap/capture-hook.sh" "$cap/create.sh"
   git init -q "$scratch" && git -C "$scratch" commit -q --allow-empty -m "Capture repository"
   ```

2. Register the hooks at user scope, in exec form, keeping a copy of `~/.claude/settings.json`.
   The `SessionStart` capture also logs the hook's parent PID, the session's CLI process, beside
   the time:

   ```bash
   if [ -e ~/.claude/settings.json ]; then
     cp ~/.claude/settings.json "$cap/settings.json.before"
   else
     echo '{}' >"$cap/settings.json.before" && touch "$cap/no-settings-before"
   fi
   jq --arg hook "$cap/capture-hook.sh" --arg create "$cap/create.sh" '
     def group($args): [{hooks: [{type: "command", command: $hook, args: $args}]}];
     .hooks = (.hooks // {}) + {
       WorktreeCreate: group(["WorktreeCreate", $create]),
       WorktreeRemove: group(["WorktreeRemove"]),
       SessionStart: group(["SessionStart", "/bin/sh", "-c",
         "echo \"$(date +%Y%m%dT%H%M%S) $PPID\" >>\"$HOME/.upool-capture/" +
           "session-start-ppid.log\""]),
       SessionEnd: group(["SessionEnd"])
     }' "$cap/settings.json.before" >"$cap/settings.json"
   ```

## Appendix: capture the project-scope hooks

From [#172](https://github.com/weslo/upool/issues/172). Before `init` registers upool's hooks in a
project's own settings (A26), this measured how the desktop app runs hooks a project registers:
the create's time, `settings.local.json` against `settings.json`, the skipped auto-trust, a
worktree's own copy of the settings, and the CLI. It ran on 2026-10-20; its results are A26's
"Measured" and `docs/evidence/project-scope-capture/`. Run it again when the desktop app changes how
it treats project hooks.

**Needs:** the Claude desktop app, with no user-scope hooks in `~/.claude/settings.json`; `jq`; a
built upool; and the Claude Code CLI.

1. Make a scratch repository under `~/Documents` that ignores `.claude/settings.local.json` and
   `.claude/worktrees/`, and a logger outside `~/Documents` that every hook runs through. The
   logger writes each hook's start and end to the millisecond, the settings it came from (its
   second argument) and its parent process, then runs `upool hook worktree-create` or
   `worktree-remove` for those events and exports `UPOOL_PROBE=scope-<source>` for `SessionStart`.
   `docs/evidence/project-scope-capture/capture.txt` has the script and both settings files.
2. Register the logger for `WorktreeCreate`, `WorktreeRemove`, `SessionStart` and
   `UserPromptSubmit` in the repository's `.claude/settings.local.json`, with `local` as the
   source.
3. Open the repository in the desktop app once, trusting it. Then run two worktree sessions there,
   each with a prompt that runs `pwd`, `echo "$UPOOL_PROBE"` and `git status`.

   **Look for:** in `main.log`, `Created hook-based worktree`, the two `Skipped …` lines and the
   session's `[CCD start-timing]` `worktree=`; in the logger's log, the create's start and end and
   `SessionStart` once per session; and `UPOOL_PROBE` set in the session.
4. Write a `UserPromptSubmit` hook with the source `worktree` into one live session's own worktree
   settings, and send that session another prompt.

   **Look for:** only `from=local` in the logger's log for that prompt.
5. Move the hooks into a committed `.claude/settings.json`, with `shared` as the source, so every
   new worktree carries a copy from its start, and run one more worktree session.

   **Look for:** the same lines as step 3, with each hook once per event.
6. From the repository, run `claude -p --worktree cli-probe "Run pwd."`.

   **Look for:** the create and `SessionStart` in the logger's log, their parent the CLI.
7. Archive the desktop sessions, and look for `Removed hook-based worktree` and the remove in the
   logger's log. Then remove the scratch repository, the logger and its log.
