# M2 manual gate

Checks that only a human on a real Mac with the Claude desktop app can run (CONTRIBUTING.md,
"Rules", rule 2). Run them on the Mac that ran the spike, record the results as a comment on the
pinned Build plan issue, and only then close the milestone and tag `v0.2.0` (docs/design.md,
Appendix A, "Stage 4: milestone gates and tags").

Each M2 issue with a manual gate adds its check here, the captures #148 takes first, and
[#81](https://github.com/weslo/upool/issues/81) puts them in order, adds the end-to-end checks and
runs them once every other M2 issue is merged. Until then some checks cannot pass: the remove and
session-start hooks are stubs, and the create hook refuses a session in a pooled repository, which
fails that session, until its pooled branch is built (#78; docs/contracts.md (a), "WorktreeCreate
output and app behaviour").

## Capture the M2 hook inputs

From [#148](https://github.com/weslo/upool/issues/148). Three M2 decisions need hook inputs, and
one timing, that the spike never captured: A11 (#16), how long the desktop app waits for a create
hook; A14 (#19), `SessionStart` for the sources other than `startup`; and A15 (#20),
`WorktreeRemove` and `SessionEnd` from a logged-in interactive CLI session (docs/contracts.md,
"Open questions").
This check adds them as new files under `testdata/captures/hooks/`, which are never edited
afterwards (CONTRIBUTING.md, "Rules", rule 1; testdata/README.md, "Re-capturing").

It needs no M2 code. The hooks it registers are `scripts/capture-hook.sh`, which saves each stdin
under `~/.upool-capture/`, wrapping a few lines of sh and git. Run it first, before "User-scope
registration": it replaces the four events' hooks in `~/.claude/settings.json` while it runs, and
step 6 puts the file back as it was.

**Needs:** the Claude desktop app; a logged-in Claude Code CLI, `claude`, in Terminal; `jq` and Go;
a checkout of upool on this check's pull request branch, `issue-148`, which is where the new files
go; and, for the desktop steps, a repository open in the desktop app: the upool checkout will do.
Each desktop session in steps 3 and 4 must be started with the app's worktree option on, or the app
runs it in the checkout itself and calls no create hook: check `main.log` for `Creating worktree
for session`.

1. Set up the capture hooks outside `~/Documents`, where the app's create-hook helper cannot read,
   and a scratch repository for the CLI session. `desk` is the desktop steps' repository. From the
   upool checkout:

   ```bash
   git switch issue-148 && git pull --ff-only
   upool=$(pwd -P)
   desk=$upool
   cap=~/.upool-capture-hooks
   scratch=~/upool-capture-repo
   mkdir -p "$cap" ~/.upool-capture
   cp scripts/capture-hook.sh "$cap/"
   cat >"$cap/create.sh" <<'EOF'
   #!/bin/sh
   # A WorktreeCreate hook for the M2 hook captures (docs/manual-gates/M2.md): it makes the
   # worktree Claude Code would make, <cwd>/.claude/worktrees/<name> on a branch <name>, and prints
   # its path, with sh, sed and git alone. With a file named slow beside it, it first logs the
   # time, sleeps 30 s, and logs the time again before it prints (A11).
   set -eu
   here=$(cd "$(dirname "$0")" && pwd -P)
   req=$(cat)
   field() {
   	printf '%s\n' "$req" | sed -n "s/.*\"$1\"[[:space:]]*:[[:space:]]*\"\([^\"]*\)\".*/\1/p"
   }
   cwd=$(field cwd)
   name=$(field name)
   if [ -e "$here/slow" ]; then
   	echo "start $(date '+%Y-%m-%d %H:%M:%S')" >>"$here/timeout.log"
   	sleep 30
   fi
   git -C "$cwd" worktree add -q "$cwd/.claude/worktrees/$name" >&2
   if [ -e "$here/slow" ]; then
   	echo "printed $(date '+%Y-%m-%d %H:%M:%S')" >>"$here/timeout.log"
   fi
   printf '%s\n' "$cwd/.claude/worktrees/$name"
   EOF
   chmod 755 "$cap/capture-hook.sh" "$cap/create.sh"
   git init -q "$scratch" && git -C "$scratch" commit -q --allow-empty -m "Capture repository"
   ```

2. Register the hooks at user scope, in exec form, keeping a copy of `~/.claude/settings.json`.
   The `SessionStart` capture also logs the hook's parent PID, the session's CLI process, beside
   the time:

   ```bash
   if [ -e ~/.claude/settings.json ]; then
     cp ~/.claude/settings.json "$cap/settings.json.before"
   else
     echo '{}' >"$cap/settings.json.before" && touch "$cap/no-settings-before"
   fi
   jq --arg hook "$cap/capture-hook.sh" --arg create "$cap/create.sh" '
     def group($args): [{hooks: [{type: "command", command: $hook, args: $args}]}];
     .hooks = (.hooks // {}) + {
       WorktreeCreate: group(["WorktreeCreate", $create]),
       WorktreeRemove: group(["WorktreeRemove"]),
       SessionStart: group(["SessionStart", "/bin/sh", "-c",
         "echo \"$(date +%Y%m%dT%H%M%S) $PPID\" >>\"$HOME/.upool-capture/" +
           "session-start-ppid.log\""]),
       SessionEnd: group(["SessionEnd"])
     }' "$cap/settings.json.before" >"$cap/settings.json"
   mkdir -p ~/.claude && cp "$cap/settings.json" ~/.claude/settings.json
   jq '.hooks | keys' ~/.claude/settings.json
   ```

   **Look for:** `SessionEnd`, `SessionStart`, `WorktreeCreate` and `WorktreeRemove` among the
   keys. Then quit the desktop app and open it again, so that it reads the new hooks.

3. **The create hook's time limit (A11).** Make the create hook slow, and note the time:

   ```bash
   touch "$cap/slow"
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

   In the desktop app, start a new session in `$desk` **with** a worktree, first prompt `pwd`, and
   wait a full minute whatever the app shows. Then, in the same shell, record the hook's log
   and the app's:

   ```bash
   rm "$cap/slow"
   cd "$upool" && {
     echo "# create.sh: when it started, and when it printed the path after sleeping 30 s"
     cat "$cap/timeout.log"
     echo "# ~/Library/Logs/Claude/main.log, worktree and hook lines from the session's start"
     awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
       grep -iE 'worktree|hook'
   } | go run ./scripts/scrubpaths --var repo="$desk" \
     >testdata/captures/hooks/desktop-create-timeout.txt
   cat testdata/captures/hooks/desktop-create-timeout.txt
   ```

   **Look for:** a `start` line and a `printed` line 30 s apart. Either the app waited, and
   `Created hook-based worktree` follows the `printed` time, or it gave up, and an error such as
   `worktree_hook_failed` comes between the two: note how many seconds after `start`. If the
   session started, archive it.

4. **`SessionStart` for each other source (A14).** In the desktop app, start a new session in
   `$desk` with a worktree, first prompt `pwd`. In that session, run `/compact`; then quit the app,
   open it again, open the session and send `pwd`, which resumes it. In a desktop session without a
   worktree, `/clear` sent no `clear` source but started a new CLI session whose `SessionStart`
   said `startup` (2026-10-20), so step 5 captures `clear` from the CLI. Then:

   ```bash
   for f in ~/.upool-capture/SessionStart-*.json; do
     printf '%s %s\n' "$(jq -r .source "$f")" "$f"
   done
   cat ~/.upool-capture/session-start-ppid.log
   ```

   **Look for:** a capture with source `startup` for this session's start and one each with
   `compact` and `resume` after it, each with `cwd` in `$desk/.claude/worktrees/`, and a parent PID
   logged at the second each capture's name gives. Then copy the newest of each of the two:

   ```bash
   cd "$upool" && for s in resume compact; do
     pick=
     for f in ~/.upool-capture/SessionStart-*.json; do
       jq -e --arg s "$s" --arg w "$desk/.claude/worktrees/" \
         '.source == $s and (.cwd | startswith($w))' "$f" >/dev/null && pick=$f
     done
     jq . "$pick" | go run ./scripts/scrubpaths --var repo="$desk" \
       >testdata/captures/hooks/session-start-$s.json
   done
   ```

   Note whether `resume`'s parent PID differs from `startup`'s: a different one is a new CLI
   process, whose PID the lease must take (A14). Archive the session.

5. **The CLI's `WorktreeRemove` and `SessionEnd` (A15).** In Terminal:

   ```bash
   touch "$cap/a15-start"
   cd "$scratch" && claude --worktree a15-probe
   ```

   Send `pwd`, then `/clear`, then `/exit`; if the CLI asks whether to keep or remove the
   worktree, remove it. Then:

   ```bash
   cd "$upool" && for e in WorktreeRemove SessionEnd; do
     find ~/.upool-capture -name "$e-*.json" -newer "$cap/a15-start"
   done
   ```

   **Look for:** a `WorktreeRemove` capture and a `SessionEnd` capture from after the marker, and a
   `SessionStart` with `source: "clear"`. Copy each that exists; one that never fired gets no file,
   and its row in testdata/README.md says so instead:

   ```bash
   cp_capture() {
     f=$(find ~/.upool-capture -name "$1-*.json" -newer "$cap/a15-start" | sort | tail -n 1)
     [ -n "$f" ] && jq . "$f" | go run ./scripts/scrubpaths --var repo="$scratch" \
       >"testdata/captures/hooks/$2"
   }
   cp_capture WorktreeRemove cli-session-remove.json
   cp_capture SessionEnd cli-session-end.json
   f=$(find ~/.upool-capture -name 'SessionStart-*.json' -newer "$cap/a15-start" \
     -exec grep -l '"source": *"clear"' {} + | sort | tail -n 1)
   [ -n "$f" ] && jq . "$f" | go run ./scripts/scrubpaths --var repo="$scratch" \
     >testdata/captures/hooks/session-start-clear.json
   ```

6. Put `~/.claude/settings.json` back as it was, then quit the desktop app and open it again:

   ```bash
   if [ -e "$cap/no-settings-before" ]; then
     rm ~/.claude/settings.json
   else
     cp "$cap/settings.json.before" ~/.claude/settings.json
   fi
   ```

   Remove `$scratch` from the desktop app, then `rm -rf "$scratch" "$cap" ~/.upool-capture`.

7. In testdata/README.md, make each row marked **pending** under captures/hooks/ name its source and
   the desktop app's and Claude Code's versions (`claude --version`) with the date, and say what it
   showed: for `desktop-create-timeout.txt`, whether the app waited 30 s or gave up and when; for
   `session-start-resume.json`, whether its parent PID was `startup`'s; for a CLI capture that never
   fired, that it never fired. Then commit, check and push. Both checks see only what git does, so
   they run after the commit:

   ```bash
   cd "$upool"
   git add testdata/captures/hooks testdata/README.md
   git commit -m "Add the M2 hook captures"
   make check-paths check-captures
   go test ./internal/hooks -run TestClassifyEveryCapture
   git push
   ```

   **Look for:** both checks and the test pass.

## User-scope registration

From [#67](https://github.com/weslo/upool/issues/67). The desktop app runs a `WorktreeCreate` hook
registered in `~/.claude/settings.json` as vouched for, and skips one from a project's settings as
"hook came from a repo-committed settings tier … (provenance not vouched)" (docs/contracts.md (a),
"WorktreeCreate output and app behaviour"; spike §8 A.2–A.5). `upool setup` registers upool
itself there for its three hooks, `upool hook <event>` in exec form, with no script between
([#163](https://github.com/weslo/upool/issues/163); A24). Built in a checkout under `~/Documents`,
as below, upool is the case A24 rests on: the desktop app's helper runs a binary there but cannot
read a file there.

**Needs:** the Claude desktop app; `jq`; upool built from `main` and first on `PATH`; and a
repository that `upool init` has made a pool of, open in the desktop app.

1. Register the hooks, and look at what setup wrote. From the upool checkout:

   ```bash
   make build
   export PATH="$(pwd -P)/bin:$PATH"
   upool setup
   jq '.hooks | {WorktreeCreate, WorktreeRemove, SessionStart}' ~/.claude/settings.json
   ```

   **Look for:** setup's lines `the hooks run <checkout>/bin/upool` and
   `updated …/.claude/settings.json` (or `created …`, if there was none) and, the first time on a
   machine that had a settings.json, `kept a copy of …/.claude/settings.json as
   …/.claude/settings.json.upool-backup`. Under each of the three events, exactly one group whose
   only handler is
   `{"type": "command", "command": "<checkout>/bin/upool", "args": ["hook", "<event>"]}`, with
   `worktree-create`, `worktree-remove` and `session-start` in turn, and every hook that was there
   before still there.

2. Run setup again.

   ```bash
   upool setup
   jq '.hooks | {WorktreeCreate, WorktreeRemove, SessionStart}' ~/.claude/settings.json
   ```

   **Look for:** `…/.claude/settings.json is up to date`, no `kept a copy` line, and the same
   `jq` output as in step 1.

3. Note the time:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

   Then start a desktop worktree session in the pooled repository: a new session in the desktop
   app, in that repository, with a worktree, and a first prompt such as `pwd`. When it has
   replied, in the same shell:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'hook-based worktree|WorktreeCreate hook|provenance not vouched'
   ```

   **Look for:** `Created hook-based worktree "<name>" at …` for this session, and no line with
   `provenance not vouched`: the helper ran upool from the checkout under `~/Documents`.

4. Archive the session.

## Subagent worktree

From [#71](https://github.com/weslo/upool/issues/71). The create hook gives a subagent's request
an ordinary worktree, detached at the repository's HEAD, at
`<repo>/.claude/worktrees/agent-<hex>`, records it in the pool's `state.json` and never leases it
a slot (docs/design.md, "Route Claude Code's worktrees through the pool: three branches in one
hook"). Subagent requests come from the bundled CLI, which can read `~/Documents` (spike §9 F.2).

**Needs:** the hooks registered as in "User-scope registration", step 1; `jq`; the pooled
repository open in the desktop app, its main checkout's absolute path in `repo` and its pool's
directory under `~/.upool/pools/` in `pool`.

1. Note the slots' state:

   ```bash
   jq '[.slots[] | {name, state}]' "$pool/state.json"
   ```

2. In the desktop app, start a session in the pooled repository **without** a worktree, as the
   spike's Test F parent session was (a session's own worktree request in a pooled repository is
   refused until the pooled branch is built), and ask:

   ```text
   Run two subagents, each with worktree isolation, that each run pwd and git status and report
   what they print.
   ```

3. When both have reported:

   ```bash
   git -C "$repo" worktree list
   jq '.agent_worktrees, [.slots[] | {name, state}]' "$pool/state.json"
   ```

   **Look for:** each subagent's `pwd` under `$repo/.claude/worktrees/agent-` followed by 17 hex
   digits, with a clean `git status`; both worktrees in `git worktree list`, `(detached HEAD)`;
   two `agent_worktrees` entries with those paths, the session's `parent_session_id` and a
   `parent_pid`; and the slots in the state step 1 showed, none of them leased.

## Pass-through on a second repository

From [#72](https://github.com/weslo/upool/issues/72). A session in a repository upool does not
manage gets the worktree Claude Code would have made, `<repo>/.claude/worktrees/<name>` on a

check before the phase ships ("Build in four phases, with the clone recipe first", phase 2): the
spike never tried it on a second repository ("What remains unverified").

**Needs:** the hooks registered as in "User-scope registration", step 1, and a git repository under
`~/Documents` that is not a pool, with at least one commit. A new one will do:

```bash
other=~/Documents/upool-pass-through
git init -q "$other" && git -C "$other" commit -q --allow-empty -m "Pass-through check"
jq -r '.repos[].path' ~/.upool/registry.json
```

**Look for:** `$other` not among the registered repositories.

1. Note the time:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

2. In the desktop app, add `$other`, start a new session in it **with** a worktree, and give it
   the first prompt `pwd`. When it has replied:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'hook-based worktree|WorktreeCreate hook|worktree_hook_failed'
   git -C "$other" worktree list
   ```

   **Look for:** the reply's `pwd` under `$other/.claude/worktrees/`; `Created hook-based worktree
   "<name>" at` that path in `main.log` and no `worktree_hook_failed`; and the worktree in
   `git worktree list` on the branch `[<name>]`.

Leave the session open: "Pass-through archive" archives it.

## Pass-through archive

From [#74](https://github.com/weslo/upool/issues/74). When a session in a pass-through worktree is
archived, the remove hook removes the worktree with `git -C <cwd> worktree remove <worktree_path>`
if it is clean as docs/contracts.md (f) defines it, and keeps it, with a line on stderr, if dirty;
the branch and its commits stay either way, and the hook exits 0 (A22). Nothing records
pass-through worktrees, so nothing else would remove one.

**Needs:** the session from "Pass-through on a second repository", still open, in the same shell.

1. Ask the session to run `echo kept > upool-pass-through.txt`, note the time, and archive it:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

2. When the session is archived:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'Removed hook-based worktree|WorktreeRemove'
   git -C "$other" worktree list
   ls "$other"/.claude/worktrees/*/upool-pass-through.txt
   ```

   **Look for:** `Removed hook-based worktree`; the worktree still in `git worktree list`; and the
   file still in it: the worktree was dirty, so it was kept.

3. Start another worktree session in `$other`, give it the first prompt `pwd`, note the time as in
   step 1 and archive it without changing anything. Then run step 2's first two commands.

   **Look for:** `Removed hook-based worktree`, and the second session's worktree gone from
   `git worktree list` and from disk, while `git -C "$other" branch` still lists its branch.

**Afterwards,** if `$other` was made for this check:

```bash
rm -rf "$other"
```

## Environment

From [#77](https://github.com/weslo/upool/issues/77). The `SessionStart` hook reads the slot from
stdin `cwd`; on `startup` it confirms the session's lease, as `upool take --confirm` does, with the
session's CLI as its holder, and exports `UNITY_PROJECT_PATH` through `CLAUDE_ENV_FILE`. On
`resume` and `compact` it exports the variable again and records the new holder, but re-copies no
agent file and runs no reset (docs/design.md, "Environment, confirmation and release";
docs/contracts.md (b); A6; A14).

**Needs:** a desktop session in one of the pool's slots, which needs the create hook's pooled
branch (#78), so this check runs with the end-to-end checks; `jq`; the pooled repository's main
checkout in `repo` and its pool's directory under `~/.upool/pools/` in `pool`.

1. Start a desktop worktree session in the pooled repository, with the first prompt:

   ```text
   Run echo "$UNITY_PROJECT_PATH" and pwd, and report what they print.
   ```

   **Look for:** both print the same slot, under `$repo/.claude/worktrees/`.

2. More than a minute after the session started, past `confirm_timeout`:

   ```bash
   cd "$repo" && upool status
   jq '.slots[] | select(.lease) | {name, state, confirmed: .lease.confirmed,
     holder_pid: .lease.holder_pid}' "$pool/state.json"
   ps -o pid,command -p "$(jq '.slots[] | select(.lease) | .lease.holder_pid' "$pool/state.json")"
   ```

   **Look for:** the session's slot `leased`, not `leased-unconfirmed`, with `confirmed: true`,
   and its `holder_pid` a running Claude Code CLI (`…/claude.app/Contents/MacOS/claude`).

3. Ask the session to append the line `<!-- environment check -->` to the slot's `CLAUDE.md`. Run
   `/compact` in it, then repeat step 1's prompt; quit the desktop app, open it again, open the
   session and repeat the prompt once more. After each, run step 2's `jq` and `ps`, and:

   ```bash
   grep -c 'environment check' "$repo"/.claude/worktrees/*/CLAUDE.md
   ```

   **Look for:** the slot after each prompt, as in step 1; the slot still `leased`, its lease
   confirmed, and after the reopen a `holder_pid` that is the session's new CLI process (A14);
   and the slot's `CLAUDE.md` still holding the line, once: neither hook run re-copied it.

## Archive

From [#73](https://github.com/weslo/upool/issues/73). About a second after a session is archived
the desktop app sends `WorktreeRemove`; the hook judges the slot with git reads alone, marks it
`needs-reset` when clean or `parked` when dirty, clears the lease and exits 0, and the app logs
"Removed hook-based worktree" with the slot still on disk (docs/contracts.md (a), WorktreeRemove
rules; (f) transitions 8 and 9; spike §8 A.6, A.8).

**Needs:** a desktop session that ran in one of the pool's slots, which needs the create hook's
pooled branch (#78), so this check runs with the end-to-end checks; the pooled repository's main
checkout in `repo`.

1. Note the time, the slot the session is in and its state:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   cd "$repo" && upool status
   ```

2. Archive the session, then:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'Removing worktree|Removed hook-based worktree|WorktreeRemove'
   upool status
   ```

   **Look for:** `Removed hook-based worktree` within a second of the archive, and the session's
   slot `needs-reset` with no lease.

3. Start another desktop session in a slot, ask it to run `echo kept > upool-archive-check.txt`,
   note the time again as in step 1, and archive it. Then run step 2's commands, and:

   ```bash
   ls "$repo"/.claude/worktrees/*/upool-archive-check.txt
   ```

   **Look for:** `Removed hook-based worktree`; the slot `parked`; and the file still in it.

**Afterwards:** the parked slot keeps the file. Resolve it as docs/manual-gates/M1.md,
"Afterwards", says: nothing in M2 hands a parked slot out again.

**Afterwards:** to take upool's hooks out again, restore the copy setup kept. It holds
settings.json as it was before upool first changed it, so a change made to the file since then
has to be made again:

```bash
cp ~/.claude/settings.json.upool-backup ~/.claude/settings.json
```
