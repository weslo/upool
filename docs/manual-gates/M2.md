# M2 manual gate

Checks that only a human on a real Mac with the Claude desktop app can run (CONTRIBUTING.md,
"Rules", rule 2). Run them on the Mac that ran the spike, record the results as a comment on the
pinned Build plan issue, and only then close the milestone and tag `v0.2.0` (docs/design.md,
Appendix A, "Stage 4: milestone gates and tags").

Each M2 issue with a manual gate adds its check here, and
[#81](https://github.com/weslo/upool/issues/81) puts them in order, adds the end-to-end checks and
runs them once every other M2 issue is merged. Until then some checks cannot pass: the remove and
session-start hooks are stubs, and the create hook refuses a session in a pooled repository, which
fails that session, until its pooled branch is built (#78; docs/contracts.md (a), "WorktreeCreate
output and app behaviour").

## User-scope registration

From [#67](https://github.com/weslo/upool/issues/67). The desktop app runs a `WorktreeCreate` hook
registered in `~/.claude/settings.json` as vouched for, and skips one from a project's settings as
"hook came from a repo-committed settings tier … (provenance not vouched)" (docs/contracts.md (a),
"WorktreeCreate output and app behaviour"; spike §8 A.2–A.5). `upool setup` registers its three
hooks there, in exec form.

**Needs:** the Claude desktop app; `jq`; upool built from `main` and first on `PATH`; and a
repository that `upool init` has made a pool of, open in the desktop app.

1. Register the hooks, and look at what setup wrote. From the upool checkout:

   ```bash
   make build
   export PATH="$(pwd -P)/bin:$PATH"
   upool setup
   jq '.hooks | {WorktreeCreate, WorktreeRemove, SessionStart}' ~/.claude/settings.json
   ```

   **Look for:** setup's line `updated …/.claude/settings.json` (or `created …`, if there was none)
   and, the first time on a machine that had a settings.json, `kept a copy of
   …/.claude/settings.json as …/.claude/settings.json.upool-backup`. Under each of the three
   events, exactly one group whose only handler is
   `{"type": "command", "command": "<home>/.upool/hooks/<script>.sh", "args": []}`, with
   `worktree-create.sh`, `worktree-remove.sh` and `session-start.sh` in turn, and every hook that
   was there before still there.

2. Run setup again.

   ```bash
   upool setup
   jq '.hooks | {WorktreeCreate, WorktreeRemove, SessionStart}' ~/.claude/settings.json
   ```

   **Look for:** `…/.claude/settings.json is up to date`, no `kept a copy` line, and the same
   `jq` output as in step 1.

3. Note the time:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

   Then start a desktop worktree session in the pooled repository: a new session in the desktop
   app, in that repository, with a worktree, and a first prompt such as `pwd`. When it has
   replied, in the same shell:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'hook-based worktree|WorktreeCreate hook|provenance not vouched'
   ```

   **Look for:** `Created hook-based worktree "<name>" at …` for this session, and no line with
   `provenance not vouched`.

4. Archive the session.

## Skill

From [#68](https://github.com/weslo/upool/issues/68). `upool setup` installs the upool skill at
user scope, in `~/.claude/skills/upool/SKILL.md` with a copy in `~/.agents/skills/upool/SKILL.md`,
and upserts upool's block into `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md` (docs/design.md,
"Hooks route, skills teach, leases and lanes keep agents from colliding": the three layers).

**Needs:** Claude Code, and `upool setup` run as in "User-scope registration", step 1.

1. Look at what setup wrote.

   ```bash
   head -n 4 ~/.claude/skills/upool/SKILL.md
   cmp ~/.claude/skills/upool/SKILL.md ~/.agents/skills/upool/SKILL.md && echo same
   grep -c '^<!-- upool:begin v' ~/.claude/CLAUDE.md ~/.codex/AGENTS.md
   ```

   **Look for:** frontmatter with `name: upool` and a description, `same`, and a count of `1` for
   each instruction file.

2. Start a new Claude Code session without a worktree, in any directory: the skill is installed
   at user scope, and a worktree session in a pooled repository cannot start until the create
   hook's pooled branch is built. Ask the agent:

   ```text
   Which skills do you have? List each by name.
   ```

   **Look for:** `upool` in the list.

## Subagent worktree

From [#71](https://github.com/weslo/upool/issues/71). The create hook gives a subagent's request
an ordinary worktree, detached at the repository's HEAD, at
`<repo>/.claude/worktrees/agent-<hex>`, records it in the pool's `state.json` and never leases it
a slot (docs/design.md, "Route Claude Code's worktrees through the pool: three branches in one
hook"). Subagent requests come from the bundled CLI, which can read `~/Documents` (spike §9 F.2).

**Needs:** the hooks registered as in "User-scope registration", step 1; `jq`; the pooled
repository open in the desktop app, its main checkout's absolute path in `repo` and its pool's
directory under `~/.upool/pools/` in `pool`.

1. Note the slots' state:

   ```bash
   jq '[.slots[] | {name, state}]' "$pool/state.json"
   ```

2. In the desktop app, start a session in the pooled repository **without** a worktree, as the
   spike's Test F parent session was (a session's own worktree request in a pooled repository is
   refused until the pooled branch is built), and ask:

   ```text
   Run two subagents, each with worktree isolation, that each run pwd and git status and report
   what they print.
   ```

3. When both have reported:

   ```bash
   git -C "$repo" worktree list
   jq '.agent_worktrees, [.slots[] | {name, state}]' "$pool/state.json"
   ```

   **Look for:** each subagent's `pwd` under `$repo/.claude/worktrees/agent-` followed by 17 hex
   digits, with a clean `git status`; both worktrees in `git worktree list`, `(detached HEAD)`;
   two `agent_worktrees` entries with those paths, the session's `parent_session_id` and a
   `parent_pid`; and the slots in the state step 1 showed, none of them leased.

## Pass-through on a second repository

From [#72](https://github.com/weslo/upool/issues/72). A session in a repository upool does not
manage gets the worktree Claude Code would have made, `<repo>/.claude/worktrees/<name>` on a
branch named `<name>`, made by git from the desktop app's restricted helper, so that the user's
other projects keep working under a hook they cannot opt out of. docs/design.md requires this
check before the phase ships ("Build in four phases, with the clone recipe first", phase 2): the
spike never tried it on a second repository ("What remains unverified").

**Needs:** the hooks registered as in "User-scope registration", step 1, and a git repository under
`~/Documents` that is not a pool, with at least one commit. A new one will do:

```bash
other=~/Documents/upool-pass-through
git init -q "$other" && git -C "$other" commit -q --allow-empty -m "Pass-through check"
jq -r '.repos[].path' ~/.upool/registry.json
```

**Look for:** `$other` not among the registered repositories.

1. Note the time:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

2. In the desktop app, add `$other`, start a new session in it **with** a worktree, and give it
   the first prompt `pwd`. When it has replied:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'hook-based worktree|WorktreeCreate hook|worktree_hook_failed'
   git -C "$other" worktree list
   ```

   **Look for:** the reply's `pwd` under `$other/.claude/worktrees/`; `Created hook-based worktree
   "<name>" at` that path in `main.log` and no `worktree_hook_failed`; and the worktree in
   `git worktree list` on the branch `[<name>]`.

3. Archive the session. The remove hook does not remove the worktree yet (#74), so afterwards, if
   `$other` was made for this check:

   ```bash
   rm -rf "$other"
   ```

**Afterwards:** to take upool's hooks out again, restore the copy setup kept. It holds
settings.json as it was before upool first changed it, so a change made to the file since then
has to be made again:

```bash
cp ~/.claude/settings.json.upool-backup ~/.claude/settings.json
```
