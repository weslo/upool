# M1 manual gate

Checks that only a human on a real Mac can run (CONTRIBUTING.md, "Rules", rule 2). Run them on the
Mac that ran the spike, with the Unity project the spike used, record the results as a comment on
the pinned Build plan issue, and only then close the milestone and tag `v0.1.0` (docs/design.md,
Appendix A, "Stage 4: milestone gates and tags").

From [#65](https://github.com/weslo/upool/issues/65). The checks run in order in one shell, which
holds the variables "Before you start" sets, and each starts from the pool the one before it left.
The pool has room for three slots (`max_slots`, default 3), and the checks use all three:

| Check | slot-1 | slot-2 | slot-3 |
|---|---|---|---|
| 1. init clones the first slot | ready | | |
| 2. The first open of slot-1 is warm | ready | | |
| 3. status, take, which, path and doctor agree | leased | | |
| 4. release resets a clean slot and parks a dirty one | parked | | |
| 5. take clones a slot when none is ready | parked | leased | |
| 6. release parks a commit on no branch | parked | parked | |
| 7. doctor finds and removes an interrupted clone | parked | parked | removed |

A parked slot keeps its work, and nothing in M1 hands it out again (docs/contracts.md (f)
transition 16: a person resolves it). That is why a release that parks moves the gate on to the
next slot, and why "Afterwards" says how to resolve the two the gate leaves.

## Before you start

**Needs:** Go, the Unity CLI (1.0.0-beta.13 or later), the Unity Editor the project uses, and a
checkout of upool on `main` with this gate merged.

1. Build upool and put it first on `PATH`, and name the project, the Editor and a scratch
   directory. From the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   make build
   export PATH="$(pwd -P)/bin:$PATH"
   upool --version
   proj=<the Unity project's absolute path>
   UNITY=/Applications/Unity/Hub/Editor/<version>/Unity.app/Contents/MacOS/Unity
   gate=$(mktemp -d)
   cd "$proj"
   upool status
   ```

   **Look for:** `upool dev`, and `upool status` saying `$proj` is not inside a registered pool: the
   gate starts from no pool. If an earlier run left one, resolve it first as "Afterwards" says.

2. Make the main checkout a good seed: open the project in Unity, let it finish importing and
   compiling, and quit the Editor (docs/design.md, "Slot lifecycle: seed only from a Library
   current at HEAD, refresh on handout, reset without `-x`").

   ```bash
   ls Library/EditorInstance.json Library/ProtocolInstance.json 2>&1
   ```

   **Look for:** both `No such file or directory`: no Editor has the project open.

## 1. init clones the first slot

The clone recipe: a whole-checkout clone under `.claude/worktrees/` that costs about no disk and
carries the gitignored agent files (docs/contracts.md (g); spike §2 TA, §9 E.1).

1. Measure the free space, time init, measure again:

   ```bash
   before=$(df -k . | awk 'NR == 2 {print $4}')
   time upool init
   after=$(df -k . | awk 'NR == 2 {print $4}')
   echo "init used $(( (before - after) / 1024 )) MB"
   slot=$proj/.claude/worktrees/slot-1
   git -C "$slot" status --porcelain
   ```

   **Look for:** init's lines end with `cloned slot-1 into …/.claude/worktrees/slot-1` and
   `registered …`; `real` about 26 s (the spike's clone took 24.6 s in the managed directory); `init
   used` under 100 MB; and `git status` printing nothing.

2. Check the agent files came with it, and the skill links resolve inside the slot:

   ```bash
   ls -d "$slot/CLAUDE.md" "$slot/AGENTS.md" "$slot/.claude" "$slot/.agents"
   find "$slot/.claude/skills" -type l ! -exec test -e {} \; -print
   grep -c '<!-- upool:begin v1 -->' CLAUDE.md
   ```

   **Look for:** all four paths listed; `find` printing nothing, so no link under
   `.claude/skills` is broken (spike §10); and `1`, the instruction block init added to the main
   checkout's `CLAUDE.md` (#53). Where the project's `CLAUDE.md` is tracked, the slot has the
   committed copy, without the block, until the block is committed.

## 2. The first open of slot-1 is warm

The point of cloning the checkout: a slot's first open imports about nothing and compiles nothing
(spike §2 TA: 37 s, 1 import, 0 assemblies compiled). The spike opened each slot in batch mode with
a log file and counted the log's `Start importing` lines (spike §3).

1. Open slot-1 the way the spike did, and count:

   ```bash
   time "$UNITY" -batchmode -quit -projectPath "$slot" -logFile "$gate/slot-1-open.log"
   echo "Unity exited $?"
   grep -c 'Start importing' "$gate/slot-1-open.log"
   grep 'Start importing' "$gate/slot-1-open.log"
   grep -n -i -w csc "$gate/slot-1-open.log" | head
   git -C "$slot" status --porcelain
   ```

   **Look for:** `Unity exited 0` after about 37 s, most of it the path-driven Bee rebuild every
   new slot path costs (spike §3); one or two imports, `ProjectSettings/EditorBuildSettings.asset`
   among them, which batch mode reimports every time; no assembly compiled, so no `Csc`
   invocation and nothing from the last `grep` (the spike's TA run had 0, against 7 for a
   git-checkout clone); and `git status` printing nothing. Ten or so imports means the main
   checkout's Library was stale when init copied it: say so in the result, with the list `grep`
   printed. If `git status` lists a change, record it in the result, then revert it with
   `git -C "$slot" checkout -- .`, so that check 4 finds the slot clean.

## 3. status, take, which, path and doctor agree

1. Lease slot-1 on a branch and ask about it from inside it:

   ```bash
   upool status
   p=$(upool take m1-gate-a --holder m1-gate)
   echo "$p"
   cd "$p"
   upool which
   upool path m1-gate-a
   git branch --show-current
   upool status
   ```

   **Look for:** the first `status` showing slot-1 `ready`; `take` printing only slot-1's path;
   `which` and `path` printing that same path; the branch `m1-gate-a`; and the second `status`
   showing slot-1 `leased` by `m1-gate`, confirmed.

2. Run doctor:

   ```bash
   upool doctor; echo "doctor exited $?"
   ```

   **Look for:** `pass` on every line, `clone-sharing` included (a 128 MB clone costing about 0 MB
   of free space), and `doctor exited 0`. `claude-code` may warn instead, saying `claude` is not
   on `PATH`, as on the spike Mac, whose Claude Code was the desktop app's bundled binary.

## 4. release resets a clean slot and parks a dirty one

The release rules: a clean slot goes back to base, a dirty one is parked with its work kept
(docs/contracts.md (f) transitions 11 and 12, and its definition of clean).

1. Commit on the branch, then release. In slot-1, still leased on `m1-gate-a`:

   ```bash
   echo gate >m1-gate-a.txt && git add m1-gate-a.txt && git commit -qm "m1 gate"
   work=$(git rev-parse HEAD)
   upool release; echo "release exited $?"
   git status --porcelain --branch | head -1
   [ "$(git rev-parse m1-gate-a)" = "$work" ] && echo "the branch kept its commit"
   ls Library/ScriptAssemblies | head -1
   ```

   **Look for:** `released slot-1: ready, detached at <base>`; `release exited 0`; `## HEAD (no
   branch)`; `the branch kept its commit`; and an assembly listed, so the Library survived the
   reset (`git clean -fd`, never `-x`).

2. Lease slot-1 again, leave an untracked file, release:

   ```bash
   cd "$(upool take m1-gate-b)"
   touch m1-gate-untracked.txt
   upool release; echo "release exited $?"
   ls m1-gate-untracked.txt
   upool status
   ```

   **Look for:** `parked slot-1, which is dirty; nothing in it was changed`, then
   `upool: warning: slot-1 is parked, not reset: ?? m1-gate-untracked.txt` (the line the spike's
   remove hook saw, testdata/captures/git/remove-status-untracked.txt); `release exited 0`; the file
   still there; and `status` showing slot-1 `parked`.

## 5. take clones a slot when none is ready

With slot-1 parked, no slot is ready, so take clones one from the main checkout, the only seed then
(docs/contracts.md (g) step 0; A19), unless the main checkout's Editor is open.

1. Open the project itself in Unity and leave it open. Then:

   ```bash
   cd "$proj"
   upool take m1-gate-c; echo "take exited $?"
   upool status
   ```

   **Look for:** `upool: not cloning a slot: no seed qualifies: … the main checkout: the Unity
   Editor has it open (Library/EditorInstance.json exists)`, then `no slot of … is ready`;
   `take exited 1`; and `status` listing slot-1 alone.

2. Quit that Editor, then:

   ```bash
   time upool take m1-gate-c
   upool status
   ```

   **Look for:** `upool: no slot is ready; cloning one from <proj>, which takes about half a
   minute`, then `upool: cloned slot-2`, and slot-2's path alone on stdout; `real` about 26 s; and
   `status` showing slot-2 `leased`.

## 6. release parks a commit on no branch

A commit on a detached HEAD is in no ref, so a reset to base would orphan it: the slot is dirty
however clean `git status` is (docs/contracts.md (f), the definition of clean; A5).

1. In slot-2, commit on a detached HEAD and release:

   ```bash
   cd "$proj/.claude/worktrees/slot-2"
   git checkout -q --detach
   echo lost >m1-gate-detached.txt && git add m1-gate-detached.txt && git commit -qm detached
   detached=$(git rev-parse HEAD)
   upool release; echo "release exited $?"
   [ "$(git rev-parse HEAD)" = "$detached" ] && echo "the commit is still checked out"
   ```

   **Look for:** `parked slot-2, which is dirty; nothing in it was changed`, then
   `upool: warning: slot-2 is parked, not reset: HEAD is on no branch`; `release exited 0`; and
   `the commit is still checked out`.

## 7. doctor finds and removes an interrupted clone

A clone that dies part-way leaves its slot `creating`, owned by a process that is gone; `doctor`
reports it and `doctor --fix` removes its worktree, its directory and its entry
(docs/contracts.md (f) transition 21; A4).

1. With slot-1 and slot-2 parked, start a take that clones slot-3, and press Ctrl-C about five
   seconds after it says it is cloning, while it copies:

   ```bash
   cd "$proj"
   upool take m1-gate-d
   ```

   Then:

   ```bash
   upool status
   upool doctor; echo "doctor exited $?"
   ```

   **Look for:** `status` showing slot-3 `creating`; doctor's slot-3 line
   `fail  slot-3  an interrupted clone: its owner, process <pid>, is gone; upool doctor --fix
   removes it`; and `doctor exited 1`. If take finished before the Ctrl-C, slot-3 is leased
   instead: release it, and run this check again with `upool take m1-gate-e`, pressing Ctrl-C
   sooner.

2. Repair it:

   ```bash
   upool doctor --fix; echo "doctor exited $?"
   ls .claude/worktrees
   git worktree list
   upool status
   ```

   **Look for:** slot-3's line `pass  slot-3  fixed: removed an interrupted clone: …`;
   `doctor exited 0` (slot-1 and slot-2 pass: parked slots are on disk and in git's list);
   `.claude/worktrees` holding slot-1 and slot-2 only; no slot-3 in `git worktree list`; and
   `status` listing slot-1 and slot-2, both `parked`.

   If slot-3's line says `removing it: … Directory not empty`, the take's `cp` outlived it, as it
   does when the take alone is signalled rather than the terminal's whole job: `pgrep -fl 'cp -cR'`
   shows it still copying into slot-3. Wait for it to finish, run `upool doctor --fix` again, and
   say so in the result.

## Record the result

Comment on the pinned Build plan issue ([#107](https://github.com/weslo/upool/issues/107)) with the
date, `sw_vers -productVersion`, `unity --version`, the commit `upool` was built from
(`git rev-parse --short HEAD` in the upool checkout), and each check's result: pass, or fail with
the lines that failed. Include check 1's time and MB and check 2's time and counts, which the next
milestones compare against. Then remove the scratch directory:

```bash
rm -rf "$gate"
```

When every check passes, close the M1 milestone, mark its README roadmap row ✅ Done and M2's 🚧 In
progress (CONTRIBUTING.md, "Documentation"), and tag `v0.1.0` on the commit the gate ran, which
starts the release workflow (docs/design.md, Appendix A, "Stage 4"). Nothing is tagged before the
gate passes.

## Afterwards

The gate leaves slot-1 and slot-2 parked, with their work kept, and the branches `m1-gate-a` to
`m1-gate-c` (and `m1-gate-e`, if check 7 ran twice). To keep the pool for real use, resolve each
parked slot by hand: remove the gate's files and commits in it, then remove the slot and let a later
take clone it again:

```bash
cd "$proj"
for s in slot-1 slot-2; do git worktree remove --force ".claude/worktrees/$s"; done
git branch -D m1-gate-a m1-gate-b m1-gate-c
```

Then edit `~/.upool/pools/<key>/state.json` to drop the two entries, or, if this is the only pool
on the Mac (`upool status --all` lists one), start over with `rm -rf ~/.upool` and `upool init`.
M1 has no command that resolves a parked slot; `prune` arrives in M4.
