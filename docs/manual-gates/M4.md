# M4 manual gate

Checks that only a human on a real Mac, with Unity Editors and the Claude desktop app, can run
(CONTRIBUTING.md, "Rules", rule 2). Run them on the Mac that ran the spike, with the Unity project
the spike used, record the results as a comment on the pinned Build plan issue, and only then close
the milestone and tag `v0.4.0` (docs/design.md, Appendix A, "Stage 4: milestone gates and tags").

From [#106](https://github.com/weslo/upool/issues/106), run again by
[#232](https://github.com/weslo/upool/issues/232) once the first run's check 8 failed. Checks 1 to
4, 6 and 9 are the ones the M4 issues added; checks 5, 7 and 8 are the end-to-end checks #106
adds. They run in order in one
shell, which holds the variables "Before you start" sets, but for check 8, which runs in a new
Terminal window so that the Homebrew upool, not the one built here, is the `upool` on `PATH`.
Check 7 tags the release candidate whose formula check 8 installs, and check 9 takes the pool
away, so it runs last. Archive desktop sessions with the app's Archive button (docs/contracts.md
A28).

## Before you start

**Needs:** the Claude desktop app, with Claude Code 2.1.295 or later; Go, `jq`, Homebrew,
GoReleaser 2.18.3 (the version release.yml pins), the Unity CLI (1.0.0-beta.13 or later), signed
in, and the Unity Editor the project uses; a checkout of upool on `main` with this gate merged; the
`HOMEBREW_TAP_TOKEN` secret (check 6); and the spike's Unity project on `main`, clean, its Editor
closed, with an `origin` you may push a throwaway branch to, and a `.worktreeinclude` naming the
local agent files that its `.gitignore` ignores, which a slot is to keep current (docs/contracts.md
A44). That file is the project owner's change. Step 2 takes upool out of the project first, if an
earlier run left it a pool, and makes `upool-gate-base` fresh from `main`.

1. **Build upool and put it first on `PATH`,** from the upool checkout:

   ```bash
   upool=$(pwd -P)
   git switch main && git pull --ff-only && make build
   export PATH="$upool/bin:$PATH"
   upool --version
   ```

2. **Make the project a pool on a throwaway base,** a branch `upool-gate-base` pushed from
   `main`, so that check 1 pushes to it rather than to `main` (maintainer decision, 2026-10-23, on
   #106). Refresh moves slots to the base `init` records, so `init` takes it from `UPOOL_BASE`:

   It first takes upool out, removes any instance file an earlier run or a crash left in the main
   checkout, which upool leaves in place when the process it names is gone (A45), and deletes any
   `upool-gate-base` an earlier run that stopped left, locally and on `origin`, so that check 1
   starts from `main`:

   ```bash
   repo=<the Unity project's main checkout, absolute>
   (cd "$repo" && upool deinit --yes)
   pgrep -fil "Unity.app/Contents/MacOS/Unity .*$repo" ||
     rm -fv "$repo/Library/EditorInstance.json" "$repo/Library/ProtocolInstance.json" \
       "$repo/Temp/UnityLockfile"
   git -C "$repo" push -q origin --delete upool-gate-base 2>/dev/null || true
   git -C "$repo" branch -D upool-gate-base 2>/dev/null || true
   git -C "$repo" branch upool-gate-base main && git -C "$repo" push -q origin upool-gate-base &&
     (cd "$repo" && UPOOL_BASE=upool-gate-base upool init)
   base=$(cd "$repo" && upool status --json | jq -r '.data.pools[0].base'); echo "$base"
   (cd "$repo" && upool status && upool doctor)
   ls "$repo/Library/EditorInstance.json" "$repo/Library/ProtocolInstance.json" \
     "$repo/Temp/UnityLockfile"
   ```

   **Look for:** `deinit` removing what an earlier run left, or saying there is nothing to remove;
   nothing from `pgrep`, so that no Editor runs for the project or a slot of it, and `rm` naming
   only what it removed (if `pgrep` prints a process, nothing is removed: quit that Editor and run
   the step again). The pattern names the Editor's binary, since the Unity Hub's helper process
   lists every Hub project's path among its arguments (#232's third run). Then `base is
   upool-gate-base, from UPOOL_BASE` from `init`; `upool-gate-base` from the `echo`; at least one
   slot `ready`; and `ls` finding none of the three files, even when `init` refreshed a stale
   Library first. That refresh closes its ready Editor plainly, which removes them (A45; #243). If
   plain closes leave it running for two minutes, it closes it with `--force` and removes them
   itself, and `init` runs up to about two and a half minutes longer (A48; #252).

## 1. Refresh

From [#97](https://github.com/weslo/upool/issues/97): `upool refresh --fetch` moves an idle ready
slot to `origin/<base>` and re-warms its Library with a headless Editor, so that the Editor
reimports only the change (docs/design.md, "Slot lifecycle: seed only from a Library current at
HEAD, refresh on handout, reset without `-x`"; docs/contracts.md (f) transitions 3 and 18). The
spike's batch open after one `.cs` edit took 11 s and rebuilt one assembly (spike §2 T2 run 3).

1. **Name a ready slot and note its assemblies:**

   ```bash
   slot=$(cd "$repo" && upool status --json |
     jq -r '[.data.pools[0].slots[] | select(.state == "ready")][0].path')
   ls -lT "$slot/Library/ScriptAssemblies" > /tmp/upool-gate-before.txt
   git -C "$slot" rev-parse HEAD
   ```

2. **Push one `.cs` change to the base branch on `origin`,** from a detached worktree outside the
   pool, by `origin`'s URL rather than its name: a push to the remote by name would move
   `origin/<base>` in the pool's own repository, which its worktrees share, and step 3 would then
   pass whether or not `refresh --fetch` fetched:

   ```bash
   edit=$(mktemp -d)/upool-gate-edit
   git -C "$repo" worktree add -q --detach "$edit" "origin/$base"
   # add a comment line to one script under "$edit/Assets/", then:
   git -C "$edit" commit -qam "upool M4 gate: one .cs change" &&
     git -C "$edit" push -q "$(git -C "$repo" remote get-url --push origin)" \
       "HEAD:refs/heads/$base" &&
     git -C "$edit" rev-parse HEAD
   git -C "$repo" worktree remove "$edit"
   git -C "$repo" rev-parse "origin/$base"
   ```

   **Look for:** the last line still the commit step 1 printed, not the one pushed, so that only a
   fetch can show refresh the change. Note the assembly the script belongs to and the commit
   pushed.

3. **Move the slot:**

   ```bash
   (cd "$repo" && time upool refresh --fetch)
   ```

   **Look for:**
   - on stderr, `moving slot-N to origin/<base> (<commit>) and re-warming it`, with `<commit>` the
     one pushed;
   - on stdout, `moved slot-N to origin/<base> (<commit>) and re-warmed it in <s> s`: record `<s>`;
   - no `did not move` and no `did not re-warm` warning.

4. **Check the slot:**

   ```bash
   git -C "$slot" rev-parse HEAD; git -C "$repo" rev-parse "origin/$base"
   (cd "$repo" && upool status); jq -c '.editors' ~/.upool/editors.json
   ls -lT "$slot/Library/ScriptAssemblies" | diff /tmp/upool-gate-before.txt -
   ```

   **Look for:** the two commits the same; the slot `ready`; the ledger `[]`; and in the diff, the
   `.dll` of the changed script's assembly, and no other, rewritten.

5. **Open the slot:**

   ```bash
   ls -lT "$slot/Library/ScriptAssemblies" > /tmp/upool-gate-before.txt
   (cd "$slot" && time upool open && upool close)
   ls -lT "$slot/Library/ScriptAssemblies" | diff /tmp/upool-gate-before.txt -
   ```

   **Look for:** `opened slot-N's Editor headless`, ready, with its time recorded; and an empty
   diff: the re-warm in step 3 did the rebuild, and the open rebuilt nothing.

**Afterwards:** `rm /tmp/upool-gate-before.txt`. The change stays on `upool-gate-base`, which
"Afterwards" at the end deletes; `main` never had it.

## 2. Close an Editor that is not ready

From [#97](https://github.com/weslo/upool/issues/97) and
[#224](https://github.com/weslo/upool/issues/224): when a re-warm's Editor is still not ready after
300 s, refresh closes it with `unity close <slot> --force`, without `save_all`, and waits for its
process to exit (docs/contracts.md A40). Plain `unity close` cannot reach a headless Editor in the
middle of a cold import, and leaves it running (`testdata/captures/unity/close-unreachable.json`).
This checks that `--force` closes one. It needs a slot whose Library can be rebuilt: a ready slot,
which this check takes and releases.

1. **Take a slot and start a cold import in it:**

   ```bash
   slot=$(cd "$repo" && upool take gate-close-unready)
   rm -rf "$slot/Library"
   unity open "$slot" --args -batchmode --format json | jq '.data.launchedPid'
   ```

   Note the PID it prints.

2. **Close it about 30 s later, while it imports,** as refresh does:

   ```bash
   unity status --project-path "$slot" --format json | jq -c '.data'
   time unity close "$slot" --force --format json | jq -c '.data'
   ps -p <pid> || echo gone
   ```

   **Look for:** no instance, or one whose state is not `ready`, before the close; `closed: true`
   from the close; and `gone`, within a minute of the close returning. Record how the close went
   (`method`, `forced` for an Editor the CLI cannot reach) and how long it took. If the Editor is
   still running, stop here: do not go on to "Afterwards" while it is up.

**Afterwards:** only once `ps -p <pid>` says the Editor is gone, delete the partial Library the
cut-short import left, so that the slot's next `upool open` finds none and is charged as a cold
import, then release the slot. Deleting it under a running Editor crashes the Editor and leaves a
crash dump in the slot, which then parks:

```bash
rm -rf "$slot/Library"
(cd "$repo" && upool release gate-close-unready && git branch -D gate-close-unready)
```

## 3. Stale seed

From [#98](https://github.com/weslo/upool/issues/98): a clone whose seed has a stale Library
refreshes it first, with a headless Editor opened, waited on until it is ready, and closed under
the ledger, then checks it again (docs/contracts.md (g) Clone recipe, step 1; docs/design.md, "Slot
lifecycle: seed only from a Library current at HEAD, refresh on handout, reset without `-x`"). A
clone of a fresh main checkout first opened with one import, EditorBuildSettings, where a clone of
a stale one imported ten (spike §2 T3b; spike §2 T2 run 1).

1. **Make the main checkout the only seed.** Take every ready slot, so that `take` clones:

   ```bash
   (cd "$repo" && upool status)
   (cd "$repo" && upool take gate-stale-1)   # and gate-stale-2, … until no slot is ready
   ```

   **Look for:** no slot `ready` or `needs-reset`, and fewer slots than `max_slots`.

2. **Take one with the main checkout's Editor open,** first while it is still starting and then
   once it has loaded. upool sees a starting Editor by the process that has the checkout as its
   `-projectpath` or holds its `Temp/UnityLockfile` open, before the Editor writes
   `Library/EditorInstance.json` (A49; #255), and then by the process that file names, a Unity
   Editor (A45; #243). Open the project's GUI Editor with `unity open`, without `-batchmode`, and
   take as soon as it returns:

   ```bash
   unity open "$repo" --format json | jq -c '.data | {launchedPid}'
   ls "$repo/Library/EditorInstance.json"
   (cd "$repo" && upool take gate-open-editor); echo "take exited $?"
   until [ -e "$repo/Library/EditorInstance.json" ]; do sleep 1; done
   jq '.process_id' "$repo/Library/EditorInstance.json"
   pgrep -fl 'Unity.app/Contents/MacOS/Unity'
   (cd "$repo" && upool take gate-open-editor); echo "take exited $?"
   (cd "$repo" && upool status)
   ```

   **Look for:**
   - `ls` finding no `EditorInstance.json` yet, and the first `take` cloning nothing, saying
     `not cloning a slot: no seed qualifies: the main checkout: the Unity Editor has it open
     (process <pid>, a Unity Editor, has it as its project)`, `<pid>` the `launchedPid` or another
     `Unity` process of that Editor's, then `no slot of <repo> is ready`, and `take exited 1`. If
     `ls` found the file already, the first `take` gives the second's reason, and the step shows
     nothing of a starting Editor: close it and start again.
   - The file's `process_id` the `launchedPid`, and among `pgrep`'s PIDs, and the second `take`
     cloning nothing the same way, but saying `(Library/EditorInstance.json names a running
     Editor)`, and `take exited 1`.
   - `status` listing no new slot.

   Only this shows that an Editor upool did not open counts, since upool knows one by the name the
   kernel gives its process, `Unity`, read from one headless Editor during #243's work.

   Then quit that Editor from its menu, or with `unity close "$repo"`, and once it has gone:

   ```bash
   ls "$repo/Library/EditorInstance.json"
   git -C "$repo" status --porcelain
   ```

   **Look for:** no `EditorInstance.json`, and nothing from `git status`, so that step 3 starts
   from a clean checkout with its Editor closed.

3. **Make the main checkout's Library stale,** with its Editor closed, by giving one script a new
   modification time without changing it, so that the checkout stays clean:

   ```bash
   touch "$repo/Assets/<a script>.cs"
   ```

   An edit would leave the checkout dirty, and the clone's step 7 would then check the script out
   again in the new slot, with a newer time still, so that the slot would be stale however well
   the refresh went (docs/contracts.md (g) step 7).

4. **Take a new slot:**

   ```bash
   (cd "$repo" && time upool take gate-stale-seed)
   ```

   **Look for:**
   - on stderr, `the Library in <repo> is stale; refreshing it with a headless Editor first`,
     then `no slot is ready; cloning one from <repo>`, then `cloned slot-N`;
   - no `stale` failure, and no `could not be closed`: a plain close that leaves the refresh's
     ready Editor running is sent again, and the Editor is closed with `--force` after two
     minutes, so the take may run up to about two and a half minutes longer (A48; #252);
   - `jq -c '.editors' ~/.upool/editors.json` printing `[]` afterwards;
   - no `Library/EditorInstance.json` or `Temp/UnityLockfile` left in `$repo` by the refresh's
     Editor (A45; #243).

5. **Open the new slot:**

   ```bash
   (cd "$repo/.claude/worktrees/slot-N" && time upool open && upool close)
   grep -A3 'InitialRefreshV2' ~/Library/Logs/Unity/Editor.log | grep 'Imports: total' | tail -1
   ```

   **Look for:** ready, its time recorded; and `Imports: total=0` from the open's first refresh:
   the seed's refresh left nothing to import, not even the touched script. `upool open` is not a
   batch `-quit` run, which reimported EditorBuildSettings in the spike; the first run saw 0.

**Afterwards:** `upool release` each `gate-stale-*` slot, then delete those branches by name.

## 4. Disk

From [#99](https://github.com/weslo/upool/issues/99): `upool status --du` reports each slot's
private size, the bytes no other clone shares, beside its apparent size, and each pool's sums
(docs/contracts.md A32). The spike put a persistent slot at about 0.4 GB: 47 MB or less for the
clone, then 321 to 337 MB rewritten by the first open at the new path (spike §4; spike §2 T2). A32
reads one private size per file, so this also times the walk over a real slot's Library.

1. **Measure the pool:**

   ```bash
   (cd "$repo" && time upool status --du)
   (cd "$repo" && upool status --du --json) | jq -c '.data.pools[0].disk'
   ```

   **Look for:**
   - each slot that has been opened and still has its Library with a private size near 0.4 GB,
     and one never opened near 47 MB or less;
   - each such slot's apparent size near the whole checkout's, several GB, far above its private
     size;
   - the slot check 2 took, whose Library it deleted, small in both: tens of MB private, and the
     checkout's apparent size without a Library;
   - the `disk:` line summing the slots;
   - how long it took: record it, with the number of files in a slot that has its Library
     (`find "$repo/.claude/worktrees/slot-N" -type f | wc -l`).

2. **Compare with `du`,** which counts a clone's shared blocks in full, on that slot:

   ```bash
   du -sh "$repo/.claude/worktrees/slot-N"
   ```

   **Look for:** a size near that slot's apparent size, and far above its private size (A32).

## 5. Prune

From [#106](https://github.com/weslo/upool/issues/106), on the prune of
[#100](https://github.com/weslo/upool/issues/100): `upool prune` lists the idle, clean, merged ready
slots beyond `ready` and changes nothing; `upool prune --yes` removes exactly those (docs/design.md,
the `prune` row; docs/contracts.md (f) transition 15). Check 3 leaves its slots released, ready and
idle; this one makes them due at once, for this shell only.

1. **List what prune would remove,** with `ready` at 1 and `shrink_after` a second:

   ```bash
   export UPOOL_READY=1 UPOOL_SHRINK_AFTER=1s
   (cd "$repo" && upool status --json) > /tmp/upool-gate-prune-before.json
   (cd "$repo" && upool prune --json) | jq -c '[.data.pools[0].candidates[] | .slot]'
   (cd "$repo" && upool prune)
   (cd "$repo" && upool status --json) |
     diff <(jq -S . /tmp/upool-gate-prune-before.json) <(jq -S . -)
   git -C "$repo" worktree list
   ```

   **Look for:** at least one line `would remove slot-N: idle …, past shrink_after 1s; beyond
   ready = 1; clean, and merged into <base>`, never the most recently used ready slot, then `this
   was a dry run: upool prune --yes removes them`; an empty diff; and every slot still in `git
   worktree list`. Note the list.

2. **Remove them:**

   ```bash
   (cd "$repo" && upool prune --yes)
   (cd "$repo" && upool status)
   git -C "$repo" worktree list
   ```

   **Look for:** `removed slot-N` for exactly the slots step 1 listed, and no `did not remove`;
   those slots gone from `upool status`, from `git worktree list` and from disk; every other slot
   as it was.

**Afterwards:** `unset UPOOL_READY UPOOL_SHRINK_AFTER` and `rm /tmp/upool-gate-prune-before.json`.

## 6. Tap token

From [#104](https://github.com/weslo/upool/issues/104): a release pushes the Homebrew formula to
weslo/homebrew-tap with a fine-grained token stored as the `HOMEBREW_TAP_TOKEN` secret; until it
exists, release.yml skips Homebrew and publishes to GitHub Releases only (docs/design.md,
"Repository, CI and Homebrew distribution"; docs/contracts.md A16). The token is the maintainer's
to make: it is a credential, and no agent creates or enters one.

1. **Rehearse the release,** from the upool checkout on `main`:

   ```bash
   make release-dry-run
   ls dist/*.tar.gz dist/checksums.txt dist/homebrew/Formula/upool.rb
   grep -A2 'test do' dist/homebrew/Formula/upool.rb
   ```

   **Look for:** both darwin archives (`darwin_amd64` and `darwin_arm64`), `checksums.txt`, and
   the formula, whose test runs `upool --version`. GoReleaser warns that `brews` is deprecated,
   which A16 accepts.

2. **Create the token** at <https://github.com/settings/personal-access-tokens/new>, signed in as
   the repositories' owner:
   - **Resource owner:** weslo.
   - **Repository access:** "Only select repositories", and only weslo/homebrew-tap.
   - **Repository permissions:** Contents, "Read and write". Metadata becomes read-only on its own;
     leave every other permission at "No access".
   - **Expiration:** as you choose. Note the date: a release after it publishes to GitHub
     Releases and then fails at the Homebrew step, since an expired token is still a secret and
     release.yml skips Homebrew only when there is none, until the secret is replaced, or deleted.

3. **Store it as the secret,** pasting the token when asked:

   ```bash
   gh secret set HOMEBREW_TAP_TOKEN --repo weslo/upool
   gh secret list --repo weslo/upool
   ```

   **Look for:** `HOMEBREW_TAP_TOKEN` in the list, and on the token's settings page, access to
   weslo/homebrew-tap only, with Contents read and write.

**Afterwards:** each release from then on pushes `Formula/upool.rb` to weslo/homebrew-tap, which is
empty until the first.
## 7. Release candidate

From [#106](https://github.com/weslo/upool/issues/106): the tap is empty until a release writes its
formula, and nothing is tagged before its gate, so the gate installs from a release candidate,

2026-10-22 and 2026-10-23, on #106; docs/design.md, "Repository, CI and Homebrew distribution",
versioning). `.goreleaser.yaml` marks a tag with a pre-release suffix a pre-release, and
CHANGELOG.md holds its notes under `## [0.4.0-rc.5]`.

1. **Tag the commit upool was built from** in "Before you start", then watch the release run once
   `gh run list` shows it:

   ```bash
   git -C "$upool" tag v0.4.0-rc.5 && git -C "$upool" push origin v0.4.0-rc.5
   gh run list --repo weslo/upool --workflow release --limit 1
   gh run watch <its ID> --repo weslo/upool --exit-status
   ```

   **Look for:** the run passing, with its GoReleaser step publishing to Homebrew, not skipping it.

2. **Check the release and the tap:**

   ```bash
   gh release view v0.4.0-rc.5 --repo weslo/upool --json isPrerelease,assets \
     --jq '{isPrerelease, assets: [.assets[].name]}'
   gh api -H 'Accept: application/vnd.github.raw' \
     repos/weslo/homebrew-tap/contents/Formula/upool.rb | grep -E 'version|url|test do' -A1
   ```

   **Look for:** `isPrerelease` true; both darwin archives and `checksums.txt`; and a formula at
   version `0.4.0-rc.5` whose URLs name `v0.4.0-rc.5` and whose test runs `upool --version`.

## 8. Quickstart on a fresh project

From [#106](https://github.com/weslo/upool/issues/106): README.md's quickstart, as written, by an
account with none of upool's state, in a Unity project made for the gate, and one desktop worktree
session that lands in a slot (docs/design.md, Appendix A, "Stage 4"). The project has no
`.worktreeinclude`, and upool writes none of its agent files (A43), so the session's slot goes back
to the pool when it is archived, where the first run's parked (#228). The session, and its
subagents, get upool's instructions from its hooks (#229). Step 7 then has a `.worktreeinclude`
name a gitignored `CLAUDE.md`, for a second session to load it (#233). A second macOS account cannot
`brew install`, since Homebrew belongs to the account that installed it, so this runs on the
maintainer's own (maintainer decision, 2026-10-23, on #106). It does not show that nothing else in
that account helps. Run it in a **new Terminal window**, without the `PATH` "Before you start"
sets.

1. **Check the slate is clean:**

   ```bash
   ls -d ~/.upool ~/.config/upool ~/.upool-probe
   env | grep '^UPOOL_'
   jq '[.hooks // {} | .[][] | .hooks[]? | select((.command // "") | test("upool"))] | length' \
     ~/.claude/settings.json
   command -v upool
   ```

   **Look for:** no directory, no variable, `0`, and no `upool`. Check 9 has not run yet, but the
   spike's pool lives in `~/.upool`: if it is there, move it aside for this check with
   `mv ~/.upool ~/.upool.gate`, and an earlier probe's `~/.upool-probe` with
   `mv ~/.upool-probe ~/.upool-probe.gate`, and put them back in step 8.

2. **Make the project,** outside `~/Documents`, as a git repository with no `origin`:

   One chain, so that nothing after a failed `unity projects create` runs, least of all `git init`
   in the window's starting directory, the home directory:

   ```bash
   repo=<the spike project's main checkout, as in "Before you start">
   src=<the upool checkout, as in "Before you start">
   gate=~/upool-gate-fresh
   version=$(awk '/m_EditorVersion:/ {print $2}' "$repo/ProjectSettings/ProjectVersion.txt") &&
     unity templates list --editor "$version" --installed | grep -F com.unity.template.urp-blank &&
     unity projects create upool-gate-fresh --path ~ --no-cloud --with-pipeline \
       --editor-version "$version" --template com.unity.template.urp-blank &&
     cd "$gate" &&
     printf '/Library/\n/Temp/\n/Logs/\n/UserSettings/\n/obj/\n/CLAUDE.md\n' > .gitignore &&
     git init -q && git add -A && git commit -qm "Fresh Unity project for the M4 gate"
   unity status --project-path "$gate" --format json | jq -c '.data'
   pgrep -fil "Unity.app/Contents/MacOS/Unity .*upool-gate-fresh" || echo none
   ```

   **Look for:** the template listed, which `unity projects create` needs named, since it cannot
   prompt for one without a terminal ("Could not resolve default template"); if another Editor
   version lists only other templates, name one of those. Then `ProjectSettings/ProjectVersion.txt`
   in `$gate`, nothing under `Library/` in `git ls-files`, and no Editor running for it: `instances`
   empty, and `none` from `pgrep`, since `unity status` lists no instance for an Editor it cannot
   reach.

3. **Run the quickstart** exactly as README.md writes it:

   ```bash
   brew install weslo/tap/upool
   command -v upool && upool --version
   cd "$gate" && upool init
   ls "$gate/CLAUDE.md" "$gate/AGENTS.md" "$gate/.worktreeinclude" "$gate/.claude/skills"
   ```

## 9. Deinit

From [#191](https://github.com/weslo/upool/issues/191): `upool deinit` takes upool out of a project,
the inverse of `upool init`, as a dry run unless `--yes`; it refuses while a slot is leased to a
live holder, parked or dirty, or has a live Editor. Run this check after every other: it takes the
pool away, and `upool init` brings it back.

1. **Note what upool put in the project,** then take the dry run:

   ```bash
   hooks() { jq '[.hooks // {} | .[][] | .hooks[]? | select(.args[0]? == "hook")] | length' \
     "$repo/.claude/settings.local.json"; }
   hooks
   (cd "$repo" && git status --porcelain && upool status)
   (cd "$repo" && upool deinit)
   (cd "$repo" && git status --porcelain && upool status)
   ```

   **Look for:** a `would remove` line for each slot, each clean `agent-*` worktree, upool's state
   and registry entry, upool's hooks in `.claude/settings.local.json`, and `.upool.toml`, and no
   block or skill, which upool no longer writes (#230); `hooks` printing 5, upool's handlers in
   exec form, `SubagentStart`'s among them; then `git status` and `upool status` as before it.

2. **Take upool out:**

   ```bash
   (cd "$repo" && upool deinit --yes)
   git -C "$repo" worktree list
   (cd "$repo" && git status --porcelain)
   hooks
   (cd "$repo" && upool status)
   ```

   **Look for:**
   - a `removed` line for each thing step 1 listed;
   - the main checkout alone in `git worktree list`;
   - `git status` as it was before `upool init`: no `.upool.toml`, and the `.claude/worktrees/`
     line still in `.gitignore`;
   - `hooks` printing 0, with the other keys of `.claude/settings.local.json` kept;
   - `upool status` failing with `is not inside a registered pool`.

3. **Start a desktop worktree session** in the project just after noting the time, then read the
   app's log from then on:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   # start the session in the desktop app, then:
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'WorktreeHooks|hook-based worktree|worktree_hook_failed'
   ```

   **Look for:** the session in the app's own worktree, `.claude/worktrees/<name>` rather than a
   `slot-N`, and no `[WorktreeHooks]` or `Created hook-based worktree` line for it.

**Afterwards:** archive the session, then pool the project again, on `main`, the base `init` then
takes from `origin`, removing no instance file by hand first:

```bash
(cd "$repo" && upool init && upool status)
```

**Look for:** `init` pooling the main checkout, with no `the Unity Editor has it open` refusal,
since an instance file counts only when the process it names is alive and is a Unity Editor (A45;
#243); and at least one slot `ready`. Whether a refresh left a file behind is for "Before you
start" and check 3 step 4 to show.
