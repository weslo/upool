# M6 manual gate

Checks that only a human on a real Mac, with a real Unity Editor, can run (CONTRIBUTING.md,
"Rules", rule 2). Run them on the Mac that ran the spike, record the results as a comment on the
pinned Build plan issue, and only then close the milestone and tag its version (docs/design.md,
Appendix A, "Stage 4: milestone gates and tags").

From [#266](https://github.com/weslo/upool/issues/266), in the Early Benchmarking milestone: every
operation that moves a slot or an Editor reports how long its steps took, on stderr, in its
`--json` envelope's `timings`, and as one line of its pool's timings log (docs/contracts.md (d),
"upool's own envelope", and (e), the timings log). The fake `unity` replies at once, so only a real
Editor shows that a step's duration is the time it really took. The checks run in order in one
Terminal shell, which holds the variables and functions "Before you start" sets, in a Unity project
made for the gate. They need no Claude desktop app.

## Before you start

**Needs:** Go; `jq`; `perl`, which macOS has; the Unity CLI (1.0.0-beta.13 or later), signed in,
and the Unity Editor the spike's project uses; and a checkout of upool on `main` with #266 merged.
No other Unity Editor may be open: check 1 watches `unity status` for the one Editor it opens.

1. **Build upool and put it first on `PATH`,** from the upool checkout:

   ```bash
   upool=$(pwd -P)
   git switch main && git pull --ff-only && make build
   export PATH="$upool/bin:$PATH"
   upool --version
   ```

2. **Make a project for the gate,** at a path no earlier run used, with a pool, and find its slot
   and its timings log:

   ```bash
   repo=<the spike's Unity project, for its Editor version>
   probe=~/upool-m6-gate-$(date +%Y%m%d%H%M)
   version=$(awk '/m_EditorVersion:/ {print $2}' "$repo/ProjectSettings/ProjectVersion.txt") &&
     unity projects create "$(basename "$probe")" --path ~ --no-cloud --with-pipeline \
       --editor-version "$version" --template com.unity.template.urp-blank &&
     cd "$probe" && printf '/Library/\n/Temp/\n/Logs/\n/UserSettings/\n/obj/\n' > .gitignore &&
     git init -q && git add -A && git commit -qm "Project for the M6 gate" &&
     upool init && upool status
   cd "$upool"
   unset UNITY_PROJECT_PATH
   key=$(jq -r --arg p "$(printf %s "$probe" | tr '[:upper:]' '[:lower:]')" \
     '.repos[] | select(.path == $p) | .key' ~/.upool/registry.json)
   log=~/.upool/pools/"$key"/timings.jsonl
   now() { perl -MTime::HiRes=time -e 'printf "%.3f\n", time'; }
   unity status --format json | jq -c '.data.instances'
   ```

   **Look for:** `cloned slot-1`, slot-1 `ready`, and `unity status` listing no Editor (`[]` or
   `null`). If it lists one, close it and run the last line again.

## 1. `upool open` reports the time to ready that `unity status` shows

`open`'s `ready` step runs from `unity open` until `unity status --until-ready` reports the Editor
ready. This checks it against an independent watch of `unity status`, polled from the moment
`upool open` starts until it first lists an Editor `ready`, and that the log line is the stderr
line's.

1. **Take slot-1 and open its Editor** while the watch runs:

   ```bash
   slot=$(cd "$probe" && upool take gate-m6)
   out=$(mktemp -t upool-m6-open)
   t0=$(now); (cd "$slot" && upool open 2> "$out") & opened=$!
   until unity status --format json 2> /dev/null |
     jq -e '.data.instances[]? | select(.state == "ready")' > /dev/null; do sleep 0.2; done
   t1=$(now); wait "$opened"; echo "open exited $?"
   cat "$out"
   echo "unity status showed ready after $(perl -e 'printf "%d", ($ARGV[1] - $ARGV[0]) * 1000' \
     "$t0" "$t1") ms"
   tail -n 1 "$log" | jq -c .
   ```

   **Look for:**
   - `open exited 0`;
   - in what `open` printed on stderr, one line `upool: timings: open slot-1: admit <a> ms, ready <r> ms; total
     <t> ms`, with `<a>` a few milliseconds, since nothing was waiting;
   - `<r>` within 1000 ms of the `unity status showed ready after` figure: the watch starts
     before the admission and polls every 0.2 s plus a `unity status` call, so it may read up to
     about a second later than `<r>`, never much earlier;
   - the log's last line with `"operation":"open"`, `"slot":"slot-1"`, `"ok":true`, steps
     `admit` and `ready` with `ms` exactly `<a>` and `<r>`, and `total_ms` exactly `<t>`.

2. **Close the Editor and release the slot,** and check their lines the same way:

   ```bash
   (cd "$slot" && upool close); (cd "$probe" && upool release gate-m6)
   tail -n 2 "$log" | jq -c '{operation, slot, ok, steps, total_ms}'
   ```

   **Look for:** a `timings: close slot-1: save_all …, close …` line and a `timings: release
   slot-1: verify …, status …, reset …, mirror …` line on stderr, each matching its log line's
   `steps` and `total_ms`, both `"ok":true`.

## Clean up

```bash
rm -f "$out"
(cd "$probe" && upool deinit --yes)
```

**Look for:** `deinit` removing slot-1 and the pool, its timings log with it. Then delete
`$probe`.
