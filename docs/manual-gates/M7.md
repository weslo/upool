# M7 manual gate

Checks that only a human on a real Mac, with the Claude desktop app or a real Unity Editor, can
run (CONTRIBUTING.md, "Rules", rule 2). Run them on the Mac that ran the spike, record the results
as a comment on the pinned Build plan issue, and only then close the milestone and tag its version
(docs/design.md, Appendix A, "Stage 4: milestone gates and tags").

From [#277](https://github.com/weslo/upool/issues/277): a leased slot whose holder is dead and
whose directory is gone, which the desktop app's record no longer names, is dropped from the pool
by `take`, `refresh` and `doctor --fix`, so that a clone can replace it within `max_slots`
(docs/contracts.md (f) transition 24). On the first benchmark run, archiving three sessions through
the app's session tool deleted each one's slot and sent upool no `WorktreeRemove`, and the pool,
at `max_slots`, could hand nothing out (docs/contracts.md (a), WorktreeRemove rules). Only the
desktop app shows an archive deleting a slot, and so that the drop meets the slot it leaves.
Check 1 needs no Unity Editor: no step of it opens one.

From [#279](https://github.com/weslo/upool/issues/279), one of the first benchmark's follow-ups
that [#288](https://github.com/weslo/upool/issues/288) tracks: every Editor upool launches is in
automation mode, `unity open <slot> --args "-automated"` for `upool open --gui` and
`--args "-batchmode -automated"` for a headless one (docs/contracts.md A33, as amended). The fake
`unity` shows the arguments upool sends; only a real Editor shows the arguments the Editor got,
and what `-automated` does to a dialog. Unity's documentation does not say what `-automated`
suppresses, so check 2 records whether it keeps a native Save panel from blocking the Editor
rather than assume it. Checks 2 to 4 need a Unity Editor and not the desktop app, and use the
slot check 1 leaves leased as `gate-m7`.

The checks run in order in one Terminal shell, which holds the variables and functions "Before
you start" sets, in a Unity project made for the gate whose `max_slots` is 1, so that the one slot
an archive leaves fills the pool, as three did on the benchmark run.

## Before you start

**Needs:** the Claude desktop app, with Claude Code 2.1.305 or later, the build the benchmark ran;
Go; `jq`; the Unity CLI (1.0.0-beta.13 or later), signed in, and the Unity Editor the spike's
project uses; a checkout of upool on `main` with #277 and #279 merged; and a second Claude Code
session, not in the gate's project, that can call the app's session tool, which check 1 archives
with. No other Unity Editor may be open: checks 2 and 3 read the log of the one Editor each opens,
which the last Editor launched writes.

1. **Build upool and put it first on `PATH`,** from the upool checkout:

   ```bash
   upool=$(pwd -P)
   git switch main && git pull --ff-only && make build
   export PATH="$upool/bin:$PATH"
   upool --version
   ```

2. **Make a project for the gate,** at a path no earlier run used, since the app keeps its record
   of a worktree by path, with a pool of one slot at most, and define `launched`, which prints
   from the Editor's log when it started, whether it is in batch mode, and which of `-batchmode`
   and `-automated` it got, one argument per line:

   ```bash
   repo=<the spike's Unity project, for its Editor version>
   probe=~/upool-m7-gate-$(date +%Y%m%d%H%M)
   version=$(awk '/m_EditorVersion:/ {print $2}' "$repo/ProjectSettings/ProjectVersion.txt") &&
     unity projects create "$(basename "$probe")" --path ~ --no-cloud --with-pipeline \
       --editor-version "$version" --template com.unity.template.urp-blank &&
     cd "$probe" && printf '/Library/\n/Temp/\n/Logs/\n/UserSettings/\n/obj/\n' > .gitignore &&
     git init -q && git add -A && git commit -qm "Project for the M7 gate" &&
     upool init && sed -i '' 's/^max_slots = 3/max_slots = 1/' .upool && upool status
   cd "$upool"
   unset UNITY_PROJECT_PATH
   record="$HOME/Library/Application Support/Claude/git-worktrees.json"
   recorded() { jq -c --arg p "$probe" '.worktrees[] | select(.path | startswith($p)) |
     {name, path, leasedBy}' "$record"; }
   key=$(jq -r --arg p "$(printf %s "$probe" | tr '[:upper:]' '[:lower:]')" \
     '.repos[] | select(.path == $p) | .key' ~/.upool/registry.json)
   lease() { jq -c --arg s "$1" '.slots[] | select(.name == $s) |
     {state, holder_pid: .lease.holder_pid}' ~/.upool/pools/"$key"/state.json; }
   editor_log=~/Library/Logs/Unity/Editor.log
   launched() {
     sed -n -e 's/^Batch mode: */batch mode /p' -e 's/^Date: */started /p' "$editor_log" |
       head -n 2
     sed -n '/^COMMAND LINE ARGUMENTS:/,/^Successfully changed project path/p' "$editor_log" |
       grep -x -e -batchmode -e -automated -e '-batchmode -automated'
   }
   grep max_slots "$probe/.upool"; recorded; lease slot-1
   unity status --format json | jq -c '.data.instances'
   ```

   **Look for:** `cloned slot-1`, slot-1 `ready`, `max_slots = 1`, nothing from `recorded`,
   `lease` printing slot-1 `ready`, and `unity status` listing no Editor (`[]` or `null`). If it
   lists one, close it and run the last line again.

## 1. A slot an archive deleted is replaced at `max_slots`

1. **Start a desktop worktree session** in `$probe` with the prompt `Run pwd with the Bash tool.
   Do nothing else.`, noting the time first:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

   Once it has answered:

   ```bash
   (cd "$probe" && upool status); lease slot-1; recorded
   ```

   **Look for:** the session's `pwd` slot-1's path; slot-1 `leased`, with a `holder_pid`, the
   session's process, which its start confirmed; the app's record naming slot-1; and no slot-2,
   since the pool is at `max_slots`.

2. **Archive the session through the app's session tool,** not with the Archive button: from the
   second Claude Code session, ask for it to be archived with the session tool (its
   `archive_session`). Then:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'Archived session|Cleaning up worktree|Removing worktree|hook-based worktree'
   ls -d "$probe/.claude/worktrees/slot-1"; recorded
   ps -p "$(lease slot-1 | jq -r .holder_pid)"
   (cd "$probe" && upool status)
   (cd "$probe" && upool doctor --json) | jq -c '.data.checks[] | select(.name == "slot-1")'
   ```

   **Look for:**
   - the app's cleanup lines, `Removing worktree … (leased by …)` and `Removed hook-based
     worktree`, for slot-1's path;
   - `ls` finding no slot-1, and nothing from `recorded`;
   - `ps` listing no process for the holder;
   - slot-1 `missing` in `upool status`;
   - from `doctor`, slot-1's `fail`, ending `its holder, process <pid>, is gone, so upool doctor
     --fix, or the next upool take or upool refresh, drops it`.

   If slot-1's directory is still on disk, this app build keeps an archived slot's directory, as
   contract (a) first recorded, and the check shows nothing of the fix: record that, with slot-1's
   state. If `ps` still lists the holder, wait for it to exit and run the step's last three lines
   again: the drop waits for a dead holder.

3. **Take a slot from Terminal,** timing it:

   ```bash
   t0=$(date +%s); slot=$(cd "$probe" && upool take gate-m7)
   echo "take exited $? after $(( $(date +%s) - t0 )) s: $slot"
   (cd "$probe" && upool status)
   ```

   **Look for:**
   - on stderr, `upool: dropped slot-1 from the pool, since its holder, process <pid>, is gone and
     its directory is not on disk`, then `upool: no slot is ready; cloning one from <the gate's
     project>, which takes about half a minute` and `upool: cloned slot-1`;
   - the `timings:` line naming `clone slot-1 <c> ms` and `handout <h> ms`, its total within a
     second or two of `<c>`;
   - `take exited 0` after about `<c>`, with `$slot` slot-1's path;
   - slot-1 `leased` in `upool status`.

   Before #277, `take` here said `could not reclaim slot-1, though its holder, process <pid>, is
   gone: <path> is not on disk` and `not cloning a slot: the pool has 1, its max_slots`, and exited
   1.

## 2. `upool open --gui` puts the Editor in automation mode, and a dialog does not block it

The first benchmark's GUI Editor, opened without `-automated`, blocked `upool close` on a native
Save panel. This checks that the Editor `upool open --gui` opens gets the argument, that a dialog
a script raises does not hold up the next command, and records what the argument does to the
Save panel and to a close with unsaved changes, which nothing documents. It uses slot-1, which
check 1 left leased as `gate-m7`, with `$slot` its path.

1. **Open the GUI Editor and read its arguments:**

   ```bash
   (cd "$slot" && upool open --gui)
   pid=$(jq '.editors[] | select(.mode == "gui") | .pid' ~/.upool/editors.json)
   ps -o command= -p "$pid"
   launched
   ```

   **Look for:** `opened slot-1's Editor gui, process <pid>: ready`; `-automated` in the process's
   command line, and no `-batchmode`; then `batch mode NO`, a `started` time from this open, and
   `-automated` on a line of its own. No `-automated` fails this check.

2. **A scripted dialog, then a following command,** against the slot's Editor:

   ```bash
   export UNITY_PROJECT_PATH=$slot
   time unity command eval 'return UnityEditor.EditorUtility.DisplayDialog("upool M7 gate",
     "A scripted dialog.", "OK", "Cancel");' --format json |
     jq -c '{success, result: .data.result.result, errors}'
   time unity command eval 'return Application.unityVersion;' --format json |
     jq -c '{success, result: .data.result.result, errors}'
   ```

   **Look for:** no dialog on screen; the first call returning `true` or `false`, which you write
   down, within a few seconds rather than timing out; and the second returning the Editor's
   version in about a second at most. A dialog that waits for a click, or either call timing out,
   fails this check: dismiss the dialog by hand.

3. **Record what a scene with no path does to `save_all`.** The benchmark's Save panel came from
   `save_all` on an open scene with no path. Note the open scene, replace it with a new one that
   has no path, save, then reopen the first:

   ```bash
   scene=$(unity command eval \
     'return UnityEngine.SceneManagement.SceneManager.GetActiveScene().path;' --format json |
     jq -r '.data.result.result')
   echo "$scene"
   unity command eval 'return UnityEditor.SceneManagement.EditorSceneManager.NewScene(
     UnityEditor.SceneManagement.NewSceneSetup.DefaultGameObjects,
     UnityEditor.SceneManagement.NewSceneMode.Single).path;' --format json |
     jq -c '{success, result: .data.result.result, errors}'
   time unity command save_all --format json | jq -c '{success, result: .data.result, errors}'
   ```

   **Look for, and record:** the template's scene path, such as `Assets/Scenes/SampleScene.unity`;
   an empty `result` for the new scene; then whether a Save panel appears in the Editor, and what
   `save_all` returned, and how long it took. If a panel appears, press Cancel in it: `-automated`
   does not keep it from blocking the Editor, which #280 handles. Either way, reopen the scene:

   ```bash
   unity command eval "return UnityEditor.SceneManagement.EditorSceneManager.OpenScene(
     \"$scene\").path;" --format json | jq -c '{success, result: .data.result.result, errors}'
   ```

   **Look for:** `$scene` as the `result`.

4. **Record what a plain close does to a scene with unsaved changes.** Without `-automated`,
   `unity close` on a dirty scene closed gracefully in 12.1 s with no dialog and discarded the
   change (spike §8 C.4); a forum report has an `-automated` Editor of 6000.5.0f1 refuse to quit
   instead (docs/contracts.md A33, as amended):

   ```bash
   unity command eval 'return UnityEditor.SceneManagement.EditorSceneManager.MarkSceneDirty(
     UnityEngine.SceneManagement.SceneManager.GetActiveScene());' --format json |
     jq -c '{success, result: .data.result.result}'
   time unity close "$slot" --format json | jq -c '{success, data, errors}'
   ps -o pid= -p "$pid" || echo "process $pid is gone"
   ```

   **Look for, and record:** `true` from the first call, then which of the two happened: the
   spike's close, `closed: true` with `method` `graceful` and the process gone; or the Editor left
   running, `closed: false`, with the code the CLI gave. In that case close it with
   `unity close "$slot" --force --format json`, and the skill's "`close` exits without saving and
   without asking" no longer describes an `-automated` Editor. Either way the ledger keeps the
   Editor's entry until the next `upool open` drops it, its process being gone.

## 3. A headless `upool open` gives the Editor `-batchmode` and `-automated` as two arguments

`unity open --args` takes one string. upool passes `"-batchmode -automated"` and relies on the
CLI to split it into the Editor's arguments, which no capture shows. A string passed whole would
reach the Editor as one argument it does not know, and the headless Editor would open with a
window.

1. **Open the default, headless, Editor, read its arguments, and close it:**

   ```bash
   (cd "$slot" && upool open)
   pid=$(jq '.editors[] | select(.mode == "headless") | .pid' ~/.upool/editors.json)
   ps -o command= -p "$pid"
   launched
   (cd "$slot" && upool close)
   ps -o pid= -p "$pid" || echo "process $pid is gone"
   ```

   **Look for:** `opened slot-1's Editor headless, process <pid>: ready`, and no Editor window;
   `-batchmode -automated` in the process's command line; then `batch mode YES`, a `started` time
   from this open, and `-batchmode` and `-automated` on two lines, not `-batchmode -automated` on
   one; then `upool close` closing it, and the process gone. A window, `batch mode NO` or the
   one-line form fails this check: the CLI passed the string whole, and A33 needs another way to
   pass two arguments.

## 4. Capture `unity open` with `-automated`

From #279's fixtures: a new capture of each `unity open` upool now sends, kept only if its
envelope differs from the one the tests replay, `open-gui-streams.json` for `--gui` and
`open-headless.json` for headless (testdata/README.md, the pending `open-automated-*` rows). The
captures go to a scratch directory first, so that nothing is added to `testdata/captures/` that
the comparison does not call for. Each runs from the upool checkout, slot-1 with no Editor.

1. **Capture each open, wait for its Editor, and close it:**

   ```bash
   scratch=$(mktemp -d -t upool-m7)
   cap() { "$upool/scripts/capture-unity.sh" -o "$scratch" --var repo="$probe" "$@"; }
   cap open-automated-gui open "$slot" --args "-automated" --format json
   unity status --until-ready --timeout 180 --format json | jq -c .data
   unity close "$slot" --format json | jq -c .data
   cap open-automated-headless open "$slot" --args "-batchmode -automated" --format json
   unity status --until-ready --timeout 180 --format json | jq -c .data
   unity close "$slot" --format json | jq -c .data
   ```

   **Look for:** `capture-unity: unity exited 0` for each, its Editor `ready`, and each close
   `closed: true`. A close that reports `PROJECTS_CLOSE_TIMEOUT` or `PROJECTS_CLOSE_UNREACHABLE`
   may come within seconds of ready: run it again half a minute later (A48).

2. **Compare each with the capture the tests replay:**

   ```bash
   shape() {
     jq -c '{success, command, data: (.data | keys), errors, warnings: (.warnings | length)}' "$1"
   }
   for pair in gui-streams:gui headless:headless; do
     old=$upool/testdata/captures/unity/open-${pair%%:*}
     new=$scratch/open-automated-${pair#*:}
     diff <(shape "$old.json") <(shape "$new.json") && echo "$(basename "$new"): same envelope"
     echo "exits: $(cat "$old.exit") then $(cat "$new.exit")"
   done
   ls "$scratch"
   ```

   **Look for:** for each, `same envelope` and `exits: 0 then 0`, or the diff. Then, in
   testdata/README.md, replace each `open-automated-*` row's **pending** with the CLI's version
   and the date, and:
   - **same envelope:** say so in the row, and add no file; the tests keep replaying the older
     capture;
   - **a diff:** copy that capture's files into `testdata/captures/unity/` (`cp -n`), say in the
     row what differs, and open an issue for the parsing change it asks for.

## Clean up

```bash
unset UNITY_PROJECT_PATH
rm -rf "$scratch"
(cd "$probe" && upool release gate-m7 && upool deinit --yes); recorded
```

**Look for:** `release` returning slot-1 to `ready`, `deinit` removing slot-1 and the pool, and
nothing from `recorded`. Then delete `$probe`, and the archived session from the app.
