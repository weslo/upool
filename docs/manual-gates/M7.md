# M7 manual gate

Checks that only a human on a real Mac, with the Claude desktop app, can run (CONTRIBUTING.md,
"Rules", rule 2). Run them on the Mac that ran the spike, record the results as a comment on the
pinned Build plan issue, and only then close the milestone and tag its version (docs/design.md,
Appendix A, "Stage 4: milestone gates and tags").

From [#277](https://github.com/weslo/upool/issues/277): a leased slot whose holder is dead and
whose directory is gone, which the desktop app's record no longer names, is dropped from the pool
by `take`, `refresh` and `doctor --fix`, so that a clone can replace it within `max_slots`
(docs/contracts.md (f) transition 24). On the first benchmark run, archiving three sessions through
the app's session tool deleted each one's slot and sent upool no `WorktreeRemove`, and the pool,
at `max_slots`, could hand nothing out (docs/contracts.md (a), WorktreeRemove rules). Only the
desktop app shows an archive deleting a slot, and so that the drop meets the slot it leaves. The
check runs in order in one Terminal shell, which holds the variables and functions "Before you
start" sets, in a Unity project made for the gate whose `max_slots` is 1, so that the one slot an
archive leaves fills the pool, as three did on the benchmark run. It needs no Unity Editor: no
step opens one.

## Before you start

**Needs:** the Claude desktop app, with Claude Code 2.1.305 or later, the build the benchmark ran;
Go; `jq`; the Unity CLI (1.0.0-beta.13 or later), signed in, and the Unity Editor the spike's
project uses; a checkout of upool on `main` with #277 merged; and a second Claude Code session,
not in the gate's project, that can call the app's session tool, which the check archives with.

1. **Build upool and put it first on `PATH`,** from the upool checkout:

   ```bash
   upool=$(pwd -P)
   git switch main && git pull --ff-only && make build
   export PATH="$upool/bin:$PATH"
   upool --version
   ```

2. **Make a project for the gate,** at a path no earlier run used, since the app keeps its record
   of a worktree by path, with a pool of one slot at most:

   ```bash
   repo=<the spike's Unity project, for its Editor version>
   probe=~/upool-m7-gate-$(date +%Y%m%d%H%M)
   version=$(awk '/m_EditorVersion:/ {print $2}' "$repo/ProjectSettings/ProjectVersion.txt") &&
     unity projects create "$(basename "$probe")" --path ~ --no-cloud --with-pipeline \
       --editor-version "$version" --template com.unity.template.urp-blank &&
     cd "$probe" && printf '/Library/\n/Temp/\n/Logs/\n/UserSettings/\n/obj/\n' > .gitignore &&
     git init -q && git add -A && git commit -qm "Project for the M7 gate" &&
     upool init && sed -i '' 's/^max_slots = 3/max_slots = 1/' .upool && upool status
   cd "$upool"
   record="$HOME/Library/Application Support/Claude/git-worktrees.json"
   recorded() { jq -c --arg p "$probe" '.worktrees[] | select(.path | startswith($p)) |
     {name, path, leasedBy}' "$record"; }
   key=$(jq -r --arg p "$(printf %s "$probe" | tr '[:upper:]' '[:lower:]')" \
     '.repos[] | select(.path == $p) | .key' ~/.upool/registry.json)
   lease() { jq -c --arg s "$1" '.slots[] | select(.name == $s) |
     {state, holder_pid: .lease.holder_pid}' ~/.upool/pools/"$key"/state.json; }
   grep max_slots "$probe/.upool"; recorded; lease slot-1
   ```

   **Look for:** `cloned slot-1`, slot-1 `ready`, `max_slots = 1`, nothing from `recorded`, and
   `lease` printing slot-1 `ready`.

## 1. A slot an archive deleted is replaced at `max_slots`

1. **Start a desktop worktree session** in `$probe` with the prompt `Run pwd with the Bash tool.
   Do nothing else.`, noting the time first:

   ```bash
   since=$(date '+%Y-%m-%d %H:%M:%S')
   ```

   Once it has answered:

   ```bash
   (cd "$probe" && upool status); lease slot-1; recorded
   ```

   **Look for:** the session's `pwd` slot-1's path; slot-1 `leased`, with a `holder_pid`, the
   session's process, which its start confirmed; the app's record naming slot-1; and no slot-2,
   since the pool is at `max_slots`.

2. **Archive the session through the app's session tool,** not with the Archive button: from the
   second Claude Code session, ask for it to be archived with the session tool (its
   `archive_session`). Then:

   ```bash
   awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
     grep -E 'Archived session|Cleaning up worktree|Removing worktree|hook-based worktree'
   ls -d "$probe/.claude/worktrees/slot-1"; recorded
   ps -p "$(lease slot-1 | jq -r .holder_pid)"
   (cd "$probe" && upool status)
   (cd "$probe" && upool doctor --json) | jq -c '.data.checks[] | select(.name == "slot-1")'
   ```

   **Look for:**
   - the app's cleanup lines, `Removing worktree … (leased by …)` and `Removed hook-based
     worktree`, for slot-1's path;
   - `ls` finding no slot-1, and nothing from `recorded`;
   - `ps` listing no process for the holder;
   - slot-1 `missing` in `upool status`;
   - from `doctor`, slot-1's `fail`, ending `its holder, process <pid>, is gone, so upool doctor
     --fix, or the next upool take or upool refresh, drops it`.

   If slot-1's directory is still on disk, this app build keeps an archived slot's directory, as
   contract (a) first recorded, and the check shows nothing of the fix: record that, with slot-1's
   state. If `ps` still lists the holder, wait for it to exit and run the step's last three lines
   again: the drop waits for a dead holder.

3. **Take a slot from Terminal,** timing it:

   ```bash
   t0=$(date +%s); slot=$(cd "$probe" && upool take gate-m7)
   echo "take exited $? after $(( $(date +%s) - t0 )) s: $slot"
   (cd "$probe" && upool status)
   ```

   **Look for:**
   - on stderr, `upool: dropped slot-1 from the pool, since its holder, process <pid>, is gone and
     its directory is not on disk`, then `upool: no slot is ready; cloning one from <the gate's
     project>, which takes about half a minute` and `upool: cloned slot-1`;
   - the `timings:` line naming `clone slot-1 <c> ms` and `handout <h> ms`, its total within a
     second or two of `<c>`;
   - `take exited 0` after about `<c>`, with `$slot` slot-1's path;
   - slot-1 `leased` in `upool status`.

   Before #277, `take` here said `could not reclaim slot-1, though its holder, process <pid>, is
   gone: <path> is not on disk` and `not cloning a slot: the pool has 1, its max_slots`, and exited
   1.

## 2. Each way of archiving, and what the hook log says

From [#278](https://github.com/weslo/upool/issues/278): each run of `upool hook <event>` appends a
line to its pool's hook log, `~/.upool/pools/<repo-key>/hooks.jsonl`, before its work and another
after it, and `doctor` reports from it the last `WorktreeRemove` of each slot the app's record no
longer names (docs/contracts.md (e), "The hook log"). Contract (a)'s archive paths were captured on
desktop app 3.1623.0 (A28), and on Claude Code 2.1.305 the session tool deleted the slots itself,
with nothing on the machine to say whether the remove hook ran ((a), "Archive paths"). This check
archives a clean and a dirty slot with the Archive button, and a clean and a dirty slot with the
session tool, on the current build, and records for each which ran the hook, in what order to the
slot directory's removal, and what the log says. It captures each remove's stdin as it goes. It
needs a upool built with #278 merged, and runs after check 1 in the same shell; check 1's Terminal
lease on slot-1 stays, and this check raises `max_slots` so that its sessions get other slots. The
gate's project is outside `~/Documents`, so this check cannot show the hold in Go's start-up that
#286 found, which logs nothing.

1. **Stand the capture hook in for upool's remove hook,** outside `~/Documents`, keeping the
   project's settings to put back. It saves each stdin under `~/.upool-capture/` and then runs the
   same upool on it, which logs as usual. Raise `max_slots` and top the pool up:

   ```bash
   cap=~/.upool-capture-hooks
   mkdir -p "$cap" ~/.upool-capture
   cp "$upool/scripts/capture-hook.sh" "$cap/" && chmod 755 "$cap/capture-hook.sh"
   settings=$probe/.claude/settings.local.json
   cp "$settings" "$cap/settings.local.json.before"
   jq --arg hook "$cap/capture-hook.sh" '.hooks.WorktreeRemove |= map(.hooks |= map(
     if .args == ["hook", "worktree-remove"]
     then . + {command: $hook, args: (["WorktreeRemove", .command] + .args)} else . end))' \
     "$cap/settings.local.json.before" >"$settings"
   jq -c '.hooks.WorktreeRemove' "$settings"
   sed -i '' 's/^max_slots = 1/max_slots = 5/' "$probe/.upool" && grep max_slots "$probe/.upool"
   (cd "$probe" && upool refresh && upool status)
   hooklog=~/.upool/pools/"$key"/hooks.jsonl
   applines='LocalSessions.archive|Archived session|Cleaning up worktree|Removing worktree'
   applines="$applines|hook-based worktree|WorktreeRemove"
   watch() { rm -f "$cap/gone"; ( while [ -d "$1" ]; do sleep 0.2; done
     date -u '+gone %Y-%m-%dT%H:%M:%SZ' >"$cap/gone" ) & watcher=$!; }
   archived() {
     awk -v since="$since" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
       grep -E "$applines"
     ls -d "$probe/.claude/worktrees/$1"; cat "$cap/gone" 2>/dev/null; recorded; lease "$1"
     jq -c --arg p "$probe/.claude/worktrees/$1" 'select(.event == "WorktreeRemove" and
       (.path | ascii_downcase) == ($p | ascii_downcase)) |
       {time, pid, phase, outcome, slot, error}' "$hooklog"
     ls -t ~/.upool-capture/
     (cd "$probe" && upool doctor --json) | jq -c --arg s "$1" '.data.checks[] |
       select(.name == "hook-log" and (.reason | startswith($s + ":")))'
   }
   since0=$(date '+%Y-%m-%d %H:%M:%S'); since0u=$(date -u '+%Y-%m-%dT%H:%M:%S')
   ```

   **Look for:** the `WorktreeRemove` handler running `$cap/capture-hook.sh` with the arguments
   `WorktreeRemove`, the upool path and `hook worktree-remove`; `max_slots = 5`; and a `ready`
   slot besides check 1's slot-1. Until step 6 puts the settings back, `doctor` fails its
   `hook-settings` check, since upool is not registered for `WorktreeRemove` itself: that is
   expected.

   Each of steps 2 to 5 starts a desktop worktree session in `$probe`, noting the time first
   (`since=$(date '+%Y-%m-%d %H:%M:%S')`), with the prompt the step gives. Once it has answered,
   set `s` to the slot its `pwd` printed, such as `s=slot-2`, and run
   `(cd "$probe" && upool status); lease "$s"; recorded`; **look for** `$s` `leased`, with a
   `holder_pid`, and the app's record naming it. Then run `watch "$probe/.claude/worktrees/$s"`,
   archive the session the way the step says, wait ten seconds, and run `archived "$s"`, which
   prints:
   - the app's lines: `LocalSessions.archive` for the Archive button, `Archived session`, and the
     cleanup, `Cleaning up worktree`, `Removing worktree … (leased by …)` and `Removed hook-based
     worktree`, if the app ran it;
   - whether the slot's directory is still on disk, and if it went, when (`gone`, UTC, to the
     second); the app's record; and the slot's state;
   - the hook log's `WorktreeRemove` lines for the slot, with their UTC times: a `start` line and
     an `end` line with the same `pid` if upool's remove hook ran, and none if it did not;
   - the capture files, newest first: a new `WorktreeRemove-<time>-<pid>.json` if the app ran the
     remove hook;
   - `doctor`'s `hook-log` line for the slot, which should say what the log does.

   The end line's `outcome` says the order: `needs-reset` or `parked` means the directory was
   still there when the hook ran `git status`; `failed`, with `checking whether slot-N is clean`,
   means the app had removed it first. If the app ran the cleanup and the log has no line, upool's
   remove hook did not reach upool's code. If the log has the remove and `~/.upool-capture` has no
   new file, the app ran the hooks it read before step 1: quit the app, open it again, and start
   the step over. Copy each new capture, from the upool checkout, to the name the step gives:

   ```bash
   (cd "$upool" && jq . "$(ls -t ~/.upool-capture/WorktreeRemove-*.json | head -n 1)" |
     go run ./scripts/scrubpaths --var repo="$probe" >"testdata/captures/hooks/<name>")
   ```

   Then `kill "$watcher" 2>/dev/null; (cd "$probe" && upool refresh)`, which drops a slot the app
   deleted (check 1) and tops the pool up for the next step.

2. **The Archive button, clean:** the prompt `Run pwd with the Bash tool. Do nothing else.`, then
   the app's Archive button. The capture is `desktop-archive-button-clean-remove.json`. On desktop
   app 3.1623.0 the app logged the cleanup and the hook marked the slot `needs-reset`, the
   directory kept (A28).

3. **The Archive button, dirty:** the prompt `Create an empty file named m7-dirty.txt with the
   Bash tool, then run git status --short. Do nothing else.`, then the Archive button. The capture
   is `desktop-archive-button-dirty-remove.json`. On 3.1623.0 the hook parked the slot with the
   file kept (A28): if the directory is gone, the file went with it, and that is the finding to
   record.

4. **The session tool, clean:** the prompt `Run pwd with the Bash tool. Do nothing else.`, then
   from the second Claude Code session, ask for the session to be archived with the app's session
   tool (its `archive_session`). The capture is `desktop-session-tool-clean-remove.json`. On
   3.1623.0 this ran the hook as the Archive button does (A28); on the benchmark's build it
   deleted the slot ((a), WorktreeRemove rules).

5. **The session tool, dirty:** the prompt of step 3, then the session tool, as in step 4. The
   capture is `desktop-session-tool-dirty-remove.json`. On 3.1623.0 the app logged `Archived
   session` and nothing more, ran no remove hook and kept its record, so that `doctor` gives the
   slot no `hook-log` line, the record still naming it, and warns on the slot's own line as A50
   has it. If the record is kept, free the slot as that warning says, unarchiving the session,
   opening it and archiving it with the Archive button, then run `archived "$s"` again and record
   that remove too; its capture is not one of the four.

6. **Put the settings back, and keep what the app logged,** from the upool checkout:

   ```bash
   kill "$watcher" 2>/dev/null; cp "$cap/settings.local.json.before" "$settings"
   cd "$upool" && {
     echo "# ~/Library/Logs/Claude/main.log, the worktree and archive lines from step 2 on"
     awk -v since="$since0" 'substr($0, 1, 19) >= since' ~/Library/Logs/Claude/main.log |
       grep -E "Creating worktree|Created hook-based worktree|$applines"
     echo "# the pool's hook log, its WorktreeCreate and WorktreeRemove lines from step 2 on (UTC)"
     jq -c --arg since "$since0u" 'select((.event == "WorktreeCreate" or
       .event == "WorktreeRemove") and .time >= $since)' "$hooklog"
   } | go run ./scripts/scrubpaths --var repo="$probe" \
     >docs/evidence/logs/desktop-archive-paths-main.log
   rm -rf "$cap" ~/.upool-capture
   (cd "$probe" && upool doctor --json) |
     jq -c '.data.checks[] | select(.name == "hook-settings")'
   ```

   **Look for:** `hook-settings` passing again, and the excerpt holding both logs' lines for each
   of steps 2 to 5. `main.log` writes local time, and the hook log UTC.

   **Record,** on the Build plan issue and in a branch with the new files, for each of steps 2 to
   5: the app's lines; whether the directory was deleted, and when against the hook log's `start`
   and `end` lines; the end line's `outcome` and `error`; `doctor`'s `hook-log` line; and the
   capture's name, or that the app ran no remove hook, in which case there is no capture. Then
   fill in the "Current build" column of docs/contracts.md (a), "Archive paths", and the four
   **pending** rows of testdata/README.md, and the **pending** row of docs/evidence/README.md for
   `logs/desktop-archive-paths-main.log`, with the versions and the date, and update A28 with what
   changed.

## Clean up

```bash
(cd "$probe" && upool release gate-m7 && upool deinit --yes); recorded
```

**Look for:** `release` returning slot-1 to `ready`, `deinit` removing slot-1 and the pool, and
nothing from `recorded`. Then delete `$probe`, and the archived session from the app.
A slot `deinit` refuses as parked holds `m7-dirty.txt` from check 2: remove it as `deinit` says,
and run `deinit` again.
