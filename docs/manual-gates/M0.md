# M0 manual gate

Checks that only a human on a real Mac can run (CONTRIBUTING.md, "Rules", rule 2). Run them on the
Mac that ran the spike, record the results as a comment on the pinned Build plan issue, and only
then close the milestone (docs/design.md, Appendix A, "Stage 4: milestone gates and tags").

Run them in the order below. The last check looks for the captures the first one adds, and the three
between them run in one shell, sharing its variables.

## Capture the M1 replies

From [#46](https://github.com/weslo/upool/issues/46). M1's `doctor` checks for Unity CLI
1.0.0-beta.13 or later and Claude Code 2.1.295 or later (docs/design.md, "One binary, a dozen
commands, one JSON file per pool"), and its staleness checks compare `unity cache key` before and
after each checkout (docs/design.md, "Slot lifecycle: seed only from a Library current at HEAD,
refresh on handout, reset without `-x`"; docs/contracts.md, A20). The spike captured none of these
replies, so this check adds them as new captures, which are never edited afterwards
(CONTRIBUTING.md, "Rules", rule 1; testdata/README.md, "Re-capturing").

**Needs:** the Unity CLI, Claude Code, `jq` and Go; the Unity project the spike used; and a checkout
of upool on this check's pull request branch, `issue-46`, which is where the new files go.

1. Record `unity --version`. From the upool checkout:

   ```bash
   git switch issue-46 && git pull --ff-only
   upool=$(pwd -P)
   scripts/capture-unity.sh version --version
   ```

   **Look for:** `capture-unity: unity exited 0`, and in `testdata/captures/unity/` a
   `version.exit` holding `0` beside `version.raw.txt` (or `version.json`, if the CLI printed
   JSON) showing 1.0.0-beta.13 or later.

2. Record the project's cache key. From the Unity project's directory, in the same shell, passing
   the project positionally as upool does (docs/contracts.md (c)). `--format json` is part of the
   script's usage: every reply under `testdata/captures/unity/` is a `--format json` envelope.

   ```bash
   cd <project>
   "$upool/scripts/capture-unity.sh" cache-key cache key "$(pwd -P)" --format json
   ```

   **Look for:** `capture-unity: unity exited 0`, and a `cache-key.json` with `"success": true` and
   the key, which the spike found built from `editor`, `packages` and `target` (spike §8 D.1),
   beside `cache-key.exit` holding `0`. The script writes the project's path as `${cwd}`.

3. Record `claude --version` with its exit code, scrubbed as hook stdin is. Use the CLI on `PATH`;
   if there is none, as on the spike Mac, first set `claude` to the desktop app's bundled binary by
   its full path (the spike's was under `~/Library/Application Support/Claude/claude-code/`, spike
   §2 Setup). In the same shell:

   ```bash
   cd "$upool" && (
     set -eu
     out=testdata/captures/claude
     if [ -e "$out/version.txt" ] || [ -e "$out/version.exit" ]; then
       echo "$out/version.* exists; captures are never overwritten" >&2
       exit 1
     fi
     raw=$(mktemp)
     trap 'rm -f "$raw" "$raw.scrubbed"' EXIT
     code=0
     "${claude:-claude}" --version >"$raw" || code=$?
     go run ./scripts/scrubpaths <"$raw" >"$raw.scrubbed"
     mkdir -p "$out"
     mv "$raw.scrubbed" "$out/version.txt"
     echo "$code" >"$out/version.exit"
   )
   ```

   **Look for:** `version.exit` holding `0`, and `version.txt` showing 2.1.295 or later.

4. In testdata/README.md, make each row marked **pending** name the files written and replace
   **pending** with the version and the date; the `claude` row also says which binary ran. If a
   script wrote a `*.stderr.txt`, it is part of its capture: keep it and name it in the row.

5. Commit, check, then push. Both checks see only what git does: `check-paths` greps tracked files
   and `check-captures` diffs commits, so they run after the commit.

   ```bash
   git status --short
   git add testdata/captures/unity testdata/captures/claude testdata/README.md
   git commit -m 'Add the captures from the M0 gate check "Capture the M1 replies"'
   make check-paths check-captures
   git push
   ```

   **Look for:** `git status` lists only the new files under `testdata/captures/unity/` and
   `testdata/captures/claude/`, and testdata/README.md; both checks pass before the push.

A version below the minimum, a nonzero exit or a failing check fails this check: say so on the pull
request instead of pushing the files.

## The fake `unity` shadows the real one

From [#47](https://github.com/weslo/upool/issues/47), check 1. Every test that needs the Unity CLI
runs the test binary as `unity`, first on `PATH` (CONTRIBUTING.md, "Testing"). CI has no Unity
installed, so there a call that missed the fake finds no `unity` at all; only on a Mac with the real
CLI and Hub could it reach them, and this check shows that none does.

**Needs:** the Unity CLI and the Unity Hub installed, Go, and a checkout of upool. This check and
the next two run in one shell: the listings for "Tests leave `~/.upool` and `~/.config/upool`
alone" are taken before this check's test run and after the next check's.

1. Quit every Unity Editor, then the Hub from its menu bar icon: an open Editor starts and stops its
   own import workers and shader compilers, which would change the listing by themselves. Then,
   from the upool checkout:

   ```bash
   git switch main && git pull --ff-only
   gate=$(mktemp -d)
   command -v unity
   ls -d "/Applications/Unity Hub.app"
   pgrep -fl Unity >"$gate/unity.before"
   wc -l <"$gate/unity.before"
   ls -laRT ~/.upool ~/.config/upool >"$gate/state.before" 2>&1
   ```

   **Look for:** `command -v unity` prints the real CLI's path, outside the upool checkout; `ls`
   prints the Hub's; and `wc` prints `0`. If it counts anything, quit what is still running and
   take the listing again. `pgrep -fl` prints whole command lines, and a running Editor's include
   its Hub access token: compare the listings only as below, and never paste them anywhere.

2. Run the tests as CI does, then list again:

   ```bash
   go test -race -shuffle=on ./... >"$gate/test.txt" 2>&1; echo "go test exited $?"
   pgrep -fl Unity >"$gate/unity.after"
   diff -q "$gate/unity.before" "$gate/unity.after" && echo "no Unity process started"
   ```

   **Look for:** `go test exited 0`; in `$gate/test.txt`, `ok` for every package with tests and no
   `FAIL`; and `no Unity process started`. `-shuffle=on` is not a flag `go test` caches results
   for, so every package ran. A failing package prints `-test.shuffle <seed>`: record the seed,
   which replays that order with `-shuffle=<seed>`. If the listings differ, the process that
   started is in `$gate/unity.after`; record its name only.

## The darwin tests pass on this Mac's home volume

From [#47](https://github.com/weslo/upool/issues/47), check 2. `internal/paths`, `internal/proc`
and `internal/statefile` have tests that run only on macOS (CONTRIBUTING.md, "Build and test"). CI
runs them on a runner's volume; this check runs them on the volume this Mac's home is on, where
upool's state lives. That volume is case-insensitive, the APFS default, and `internal/paths` must
say so, because a path key folds case only on such a volume (docs/design.md, "Repository, CI and
Homebrew distribution").

**Needs:** the shell from the previous check.

1. Run the three packages with their temporary directories under the home directory:

   ```bash
   tmp=$(mktemp -d ~/upool-gate.XXXXXX)
   TMPDIR="$tmp/" go test -race -count=1 -v ./internal/paths ./internal/proc ./internal/statefile \
     >"$gate/darwin.txt" 2>&1; echo "go test exited $?"
   grep -E '^(--- |ok|FAIL)' "$gate/darwin.txt"
   ```

   **Look for:** `go test exited 0`; `ok` for each package; no `--- FAIL` or `--- SKIP`; and
   `--- PASS` for each darwin test: `TestKeyJoinsPrivateTmp` and
   `TestCaseSensitiveAgreesWithTheVolume` in paths; `TestStartIsWhenTheChildStarted`,
   `TestAliveFalseForReapedChild`, `TestStartOfReapedChildIsErrNoProcess`,
   `TestAliveTrueForThisProcess`, `TestAliveFalseForWrongStartTime` and
   `TestSystemAgreesWithStartAndAlive` in proc; and `TestLockExcludesSecondProcess`,
   `TestGivingUpLeavesNoLockBehind` and `TestConcurrentUpdatesLoseNothing` in statefile.

2. Show that the run was on the home volume, and what that volume is:

   ```bash
   [ "$(stat -f %d "$tmp")" = "$(stat -f %d ~)" ] && echo "same volume as home"
   diskutil info "$(stat -f %Sd ~)" | grep Personality
   rm -rf "$tmp"
   ```

   **Look for:** `same volume as home`, and `File System Personality: APFS`, not
   `Case-sensitive APFS`. `TestCaseSensitiveAgreesWithTheVolume` fails unless `paths.CaseSensitive`
   agrees with what the volume does (a file opens by its name in another case), so its pass on a
   volume `diskutil` calls case-insensitive means `internal/paths` reported it case-insensitive.

## Tests leave `~/.upool` and `~/.config/upool` alone

From [#47](https://github.com/weslo/upool/issues/47), check 3. Every test sets `HOME` to a
temporary directory (CONTRIBUTING.md, "Testing"), so no test reads or writes this Mac's state or
configuration. A test that missed it would still pass, on CI and here; only the real directories
show it.

**Needs:** the shell from the two previous checks, whose test runs this check's listings bracket.

1. List again and compare:

   ```bash
   ls -laRT ~/.upool ~/.config/upool >"$gate/state.after" 2>&1
   diff "$gate/state.before" "$gate/state.after" && echo "state untouched"
   ```

   **Look for:** `state untouched`. `-T` lists full modification times, and each directory's own
   `.` line changes when anything is added to it or removed from it. Where neither directory
   exists, as on a Mac that has never run upool, both listings hold the same two
   `No such file or directory` lines, which counts as identical.

## The M1 captures are in place

From [#47](https://github.com/weslo/upool/issues/47), check 4. M1's `doctor` and staleness checks
are tested against the captures "Capture the M1 replies" adds (CONTRIBUTING.md, "Rules", rule 1),
so M1 cannot start without them.

**Needs:** the upool checkout, with those captures committed.

1. From the checkout:

   ```bash
   git ls-files 'testdata/captures/unity/version.*' 'testdata/captures/unity/cache-key.*' \
     testdata/captures/claude
   grep -c '| \*\*pending\*\* |' testdata/README.md
   make check-paths check-captures BASE=da59a69; echo "make exited $?"
   ```

   **Look for:** under `testdata/captures/unity/`, `version.exit` beside `version.raw.txt` or
   `version.json`, and `cache-key.json` and `cache-key.exit`; under `testdata/captures/claude/`,
   `version.txt` and `version.exit`; any `*.stderr.txt` the script wrote, which testdata/README.md
   then names; `0` from `grep`, so no row in testdata/README.md is still pending; and
   `make exited 0`, with no `check-paths:` or `check-captures:` line. `da59a69` is the commit that
   merged #46: with the default `BASE`, `origin/main`, an up-to-date `main` would compare itself
   with itself, and `check-captures` would look at nothing.

Comment on the pinned Build plan issue ([#107](https://github.com/weslo/upool/issues/107)) with the
date, `sw_vers -productVersion`, `go version` and `unity --version`, and each check's result: pass,
or fail with the lines that failed. Leave out the `pgrep` listings. Then remove the scratch

